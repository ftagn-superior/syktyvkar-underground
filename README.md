# Syktyvkar Underground

Небольшая браузерная сетевая технодемо: участок Сыктывкара от кольца Коммунистической и Октябрьского проспекта до Бани №4 и Школы №1, до восьми игроков, столкновения и один общий физический ящик. Собственный персонаж реагирует с локальным предсказанием; сервер рассчитывает общий мир. Основа — **Babylon.js + Havok + Colyseus, TypeScript и Vite**.

## Локальный запуск

Нужен **Node.js 24 или новее**; проверенное окружение записано в `.node-version`. Все команды выполняются из корня репозитория. Глобальная установка pnpm не обязательна:

```sh
npx --yes pnpm@12.18.0 install --frozen-lockfile
npx --yes pnpm@12.18.0 dev
```

Откройте **http://127.0.0.1:5173** и нажмите «Войти». Для второго игрока откройте этот же адрес в новой вкладке или другом браузере. Если pnpm 12.18.0 уже установлен, можно использовать обычные `pnpm install --frozen-lockfile` и `pnpm dev`.

- **WASD / стрелки** — движение относительно экрана; подойдите к ящику, чтобы толкнуть его.
- **Удерживайте Shift** — быстрый бег: 14 м/с вместо обычных 4 м/с (в 3,5 раза быстрее). Работают оба Shift; при отпускании возвращается обычная скорость. Скорости задаются в `simulation.character.speed` и `sprintSpeed` файла мира и одинаково применяются сервером и предсказанием клиента.
- **Q / E** или кнопки **↶ / ↷** — плавный поворот камеры на 90°. Управление учитывает текущий ракурс. Стены, крыши и детали домов, закрывающих вашего персонажа, автоматически становятся полупрозрачными; столкновения сохраняются.
- **Колёсико мыши** — приблизить или отдалить кадр (от 0,6 до 30 исходного масштаба).
- **На старт** — безопасное возвращение своего персонажа. Кнопка показывает ожидание подтверждения сервера, затем отсчитывает три секунды до следующего возврата.
- **Выйти** — сразу освободить место. При закрытии или обновлении вкладки сессия сохраняется на 30 секунд; повторный вход в той же вкладке восстанавливает персонажа.
- Кнопка **Диагностика** открывает показатели соединения, кадров и коррекций.
- `Ctrl+C` в консоли останавливает оба процесса. После перезапуска сервера мир начинает заново.

Целевой браузер — настольный Chromium/Chrome с WebGL2 и клавиатурой. Работающие приложения не загружают движок, WASM, шрифты или другие ресурсы с внешних CDN. Интернет нужен для первоначальной установки зависимостей.

В панели диагностики можно выбрать качество **«Обычное»** или **«Экономное»**. Экономный режим отключает тени и уменьшает ширину и высоту внутреннего изображения до ⅔ обычного; выбор сохраняется в браузере. После смены качества измерения кадров начинаются заново с 60-секундного прогрева видимой игры. **«Скачать отчёт»** сохраняет JSON со сведениями о сборке, версиях мира и протокола, окне браузера, качестве графики, кадрах и соединении.

При потере графического контекста управление останавливается и появляется постоянное сообщение. После автоматического восстановления графики можно продолжить новым нажатием клавиши. Если восстановление не происходит, в сообщении доступна кнопка перезагрузки страницы.

`pnpm dev` собирает данные мира и запускает Vite на порту **5173**, сервер — на **2567**. Освободите эти порты, если они заняты. Изменения TypeScript подхватываются автоматически; после изменения JSON-сцены перезапустите команду. По умолчанию оба процесса доступны только с текущего компьютера.

Сервер запускает городской участок `ring-block`. Прежняя тестовая площадка собирается вместе с ним и запускается переменной `SU_WORLD=physics-lab` (например, `SU_WORLD=physics-lab node dist/server/main.mjs`); автоматические тесты используют её по умолчанию. Как устроен участок и как его пересобрать из прототипа — в [описании участка](docs/ring-block.md).

## Собранная версия

Если установлен `make`, пересобрать приложение и запустить сервер можно одной командой:

```sh
make run
```

Просто `make` выполняет то же самое. Перед первым запуском установите зависимости командой `make install`. Нужен Node.js 24 или новее; Makefile использует pnpm 12.18.0 через `npx`, поэтому глобальная установка pnpm не обязательна. При ошибке сборки сервер не запускается.

Отдельно доступны `make build` (сборка) и `make start` (запуск уже собранной версии). Переменные окружения передаются серверу, например: `HOST=127.0.0.1 PORT=2567 make run`. Остановка — `Ctrl+C`.

Те же действия без `make`, после установки зависимостей:

```sh
npx --yes pnpm@12.18.0 build
npx --yes pnpm@12.18.0 start
```

Откройте **http://127.0.0.1:2567**. Один Node.js-процесс обслуживает клиент, данные мира и WebSocket. Сборка находится в `dist/`, включая локальную копию Havok WASM. Запускать `start` нужно из корня репозитория; после изменений исходников повторите `build`. Docker, база данных, CI и публикация для локальной работы не нужны.

## Ручной запуск через meta.ftagn.xyz

На сервере `ftagn.xyz` Caddy направляет **https://meta.ftagn.xyz** на **127.0.0.1:2567**. Используется собранная версия: один процесс обслуживает страницу, API и WebSocket игры. Порт **5173** относится только к Vite в режиме `dev`; домен настроен на порт **2567**.

В консоли сервера подготовьте сборку из корня проекта (при первом запуске или после обновления исходников):

```sh
cd /root/local-repo/syktyvkar-underground
npx --yes pnpm@12.18.0 install --frozen-lockfile
npx --yes pnpm@12.18.0 build
```

Затем запускайте приложение одной командой из этого же каталога:

```sh
HOST=127.0.0.1 PORT=2567 node dist/server/main.mjs
```

Для пересборки и запуска одной командой из текущего рабочего каталога используйте `make run`.

Откройте **https://meta.ftagn.xyz** и нажмите «Войти». Процесс работает в текущей консоли, журналы выводятся туда же; `Ctrl+C` останавливает игру. Для работы после отключения SSH можно запускать эту команду внутри `tmux`. Пока процесс остановлен, домен возвращает **502 Bad Gateway**. При новом запуске состояние мира сбрасывается. CI, Docker, deploy и отдельный сервис приложения для этого режима не требуются.

Проверка при запущенном приложении:

```sh
curl -fsS https://meta.ftagn.xyz/health/ready
# {"ready":true}
```

Настройка домена находится на сервере в `/etc/caddy/sites/meta.ftagn.xyz.caddy`; её подключает существующий `/etc/caddy/Caddyfile`:

```caddyfile
meta.ftagn.xyz {
    encode zstd gzip
    reverse_proxy 127.0.0.1:2567
}
```

Caddy обслуживает HTTPS и перенаправляет HTTP на HTTPS. [Обычный `reverse_proxy` поддерживает WebSocket](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#streaming), поэтому отдельные маршруты для игрового соединения не нужны. Перезапуск игры и пересборка не требуют перезагрузки Caddy. Чтобы удалить только этот домен, удалите его `.caddy`-файл, затем выполните `caddy validate --config /etc/caddy/Caddyfile && systemctl reload caddy`.

## Проверки

```sh
pnpm check
pnpm test
pnpm build
# В отдельной консоли при запущенном сервере:
pnpm load -- --clients 6 --seconds 60 --scenario crowd
```

Нагрузка использует обычный клиентский SDK и настоящие команды движения. Для восьми участников дополнительно войдите из двух браузеров. Есть сценарии `crowd` (скопление у ящика) и `spread` (движение по площадке); `--seconds 1800` запускает 30-минутный прогон. `--report output/validation/load.json` сохраняет результат в существующий каталог; `--url http://127.0.0.1:2567` задаёт сервер.

Для проверок в настоящем Chromium сначала установите тестовый браузер:

```sh
pnpm exec playwright install chromium
pnpm test:physics:browser
# После pnpm build — дома, камера и загрузка моделей со своими серверами:
pnpm test:buildings:browser
pnpm test:assets:browser
# После pnpm build — проверка перезапуска со своим сервером:
pnpm test:restart:browser
# При запущенной собранной версии на порту 2567:
pnpm test:browser
pnpm test:polish:browser
pnpm test:render:browser
pnpm test:soak
```

`test:physics:browser` запускает свой временный сервер и сравнивает Havok в Node.js и браузере. `test:browser` проверяет два независимых контекста, заполнение мира, управление и восстановление; `test:soak` выполняет 30-минутный прогон с шестью SDK-клиентами и двумя браузерами. Для двух последних нужен пустой тестовый мир. Адрес можно изменить переменной `SU_TEST_URL`, длительность прогона — `SU_SOAK_SECONDS`; путь к уже установленному Chromium — `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Браузерные сценарии сохраняют свидетельства в `output/`, который исключён из Git. Используется программный рендерер, поэтому эти сценарии проверяют поведение, а бюджет кадров нужно измерять на целевом компьютере с GPU.

`test:buildings:browser` проверяет повторное использование GLB, независимую прозрачность у двух игроков и у копий дома, поворот камеры, движение с четырёх ракурсов и сохранение столкновений. `test:assets:browser` проверяет восстановление после повреждения браузерного кэша и отказ входа при неверных ресурсах.

`test:polish:browser` проверяет обратную связь возврата, потерю фокуса и графического контекста, выбор качества, выгрузку отчёта и доступность интерфейса в небольших окнах. `test:render:browser` сравнивает режимы графики с одним неподвижным игроком при 1280 × 720: по умолчанию по 10 секунд прогрева и 15 секунд измерения на режим. Обоим нужен запущенный сервер; для сравнения графики оставьте мир без других участников. Это короткое сравнительное измерение, не аппаратная приёмка T04. Параметры `SU_PROFILE_WARMUP_MS`, `SU_PROFILE_SAMPLE_MS`, `SU_PROFILE_QUALITIES` (`standard,economy`) и `SU_PROFILE_OUTPUT` задают интервалы, режимы и путь к результату. `SU_TEST_RENDERER=hardware` убирает принудительный SwiftShader; фактически выбранный рендерер записывается в отчёт.

`pnpm test:network` отдельно запускает собственный мир для каждого профиля задержки, записывает две браузерные сессии и измеряет коррекции. Перед ним выполните `pnpm build` и `pnpm exec playwright install chromium ffmpeg`. Дополнительный `pnpm test:network:netem` проверяет потери TCP-пакетов в изолированном Linux network namespace; ему нужны `unshare`, `ip`, `tc`, `curl` и соответствующие права. Для запуска самой игры эти инструменты не требуются.

Проверки физики и контрактов лежат рядом с пакетами, сетевые — в `tests/integration`. Результаты фактических проверок и ограничения окружения записываются в `reports/`. Результат на восьми клиентах не означает готовности мира на 50 игроков.

## Устройство проекта

| Путь | Ответственность |
|---|---|
| `apps/client` | Babylon-сцена, управление, соединение, предсказание и интерфейс |
| `apps/server` | Одна Colyseus-комната, сессии, проверки команд и публикация состояния |
| `packages/contracts` | Независимые от движка типы, проверка данных и параметры протокола |
| `packages/protocol` | Сетевые схемы и преобразование снимков |
| `packages/simulation` | Общая 3D-физика, контроллер, серверный мир и мир предсказания |
| `content/worlds/ring-block` | Городской участок: настройки импорта `import.json` и сгенерированные мир и ячейка |
| `content/buildings/ring-block` | Сгенерированные модели участка: дома по контурам OSM, земля, деревья |
| `content/worlds/physics-lab/world.json` | Тестовая площадка: препятствия, точки появления и физические параметры |
| `content/worlds/physics-lab/cells` | Экземпляры домов: устойчивые ID, ссылки на модели и размещение |
| `content/buildings` | Каталог моделей и исходники геометрии; рецепты или подготовленные GLB |
| `tools/world-build` | Импорт участка из прототипа, проверка сцены и повторяемая сборка с хешами |
| `tools/load-test` | Активные сетевые клиенты для измерений |

Стена добавляется в JSON-сцену; масса и форма ящика также задаются данными. `pnpm world:build` выпускает согласованные артефакты клиента и сервера. Сущности имеют устойчивые ID; определение объекта, физическое состояние и визуальное представление разделены. Изменение мира применяется при перезапуске, несовместимый клиент не допускается к игре. При несовместимом изменении контрактов или общих правил движения нужно увеличить `PROTOCOL_VERSION` и пересобрать обе стороны.

Одноэтажный дом имеет основание 8 × 6 м и высоту 4,5 м, двухэтажный — 8 × 10 м и 7,5 м. Интерьеров пока нет. Мир использует формат v2: визуальные GLB, коллайдеры, семантические части и размещение хранятся отдельно и связаны проверяемыми хешами. Повторяющиеся дома используют одну геометрию, сохраняя независимую прозрачность. Подготовленные сложные формы поддерживаются через составные коллайдеры и статические треугольные сетки. Как добавить модель или поставить её копию — в [инструкции по домам](docs/building-assets.md).

Предсказание использует общие правила движения и отдельный физический мир. Ящик рассчитывается сервером; в прогнозе персонажа используется приближённая форма. Прыжки, платформа, транспорт, прямой импорт из OSM, аккаунты и сохранения оставлены следующим итерациям.
