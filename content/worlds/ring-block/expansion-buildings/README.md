# Дома-коробки новой территории ring-block

Временные здания этапа B [плана расширения](../../../../docs/plans/city-expansion.md):
по одной простой призме на каждый контур OpenStreetMap вне старой области
(X −269…331, Z −745…131). Окон, дверей, деталей и подсветки нет. Их задача — проверить
нагрузку на клиент до детализации; на этапе C рецепты заменяются болванками по типам
застройки с теми же `assetId`/`entityId`, поэтому размещения в БД переносить не придётся.

Данные © участники OpenStreetMap, лицензия [ODbL 1.0](https://opendatacommons.org/licenses/odbl/).
Запрос, время снимка, SHA-256, счётчики и причины пропусков — в `provenance.json`.

## Что пишет генератор

`pnpm world:boxes:expansion` (`tools/world-build/src/expansion-boxes.ts`) — разовая
команда, `pnpm world:build` OSM не читает.

| Куда                                                       | Что                                                            |
| ---------------------------------------------------------- | -------------------------------------------------------------- |
| `content/buildings/ring-block/expansion/<id>/`             | `asset.json` + рецепт `footprint` с `windows: false`           |
| `content/buildings/ring-block/catalog.json`                | записи `<id>` → `expansion/<id>/asset.json`                    |
| `content/worlds/ring-block/cells/expansion-buildings.json` | экземпляры (отдельная исходная ячейка, `0_0.json` не меняется) |
| `content/worlds/ring-block/terrain-release.json`           | только `seedY` — высота низа коробки                           |

ID: `osm-way-<id>`, для мультиполигона — `osm-relation-<id>` (несколько внешних контуров —
суффиксы `-1`, `-2`…). Начало модели — центр охвата контура, поворот нулевой.
Внутренние контуры (дворы-колодцы) коробкой не вырезаются.

Цоколь входит в саму призму: низ коробки на 0,3 м ниже самой низкой точки рельефа под
контуром, пол первого этажа — там же, где его поставил бы фундамент `foundation-v2`
(высшая точка + 0,08 м). Отдельных правил фундамента и политик размещения у коробок нет:
при публикации каждое правило превращается в отдельную модель фундамента на экземпляр,
и 1830 таких моделей вывели мир за предел 10 000 ссылок на здания (замер этапа B).
Поэтому коробки нельзя ставить из игры, а при смене рельефа генератор нужно перезапустить.

Высота — `building:levels` × 3 м; без тега — `height` / 3, иначе по типу `building`:
жилой многоквартирный 5 этажей, частный дом 2, гараж/сарай 1, служебный 2,
общественный 3, прочие 2. Пропускаются навесы (`roof`, `carport`), руины, стадионы (контур охватывает поле), контуры
площадью меньше 4 м², самопересекающиеся контуры, а также всё, чей охват задевает
старую область или полосу 4 м у края мира.

После запуска генератора нужен `pnpm world:build` и новый пин `terrain-release.json` → `expected`
(только на Linux, см. план).

## Пересчёт

```sh
pnpm world:boxes:expansion -- --fetch   # новый снимок Overpass → output/expansion-buildings/osm.json
pnpm world:boxes:expansion              # пересчитать из сохранённого снимка
```

Повторный запуск удаляет прежние коробки (папку `expansion/`, их записи в каталоге,
фундаменты, политики и `seedY`) и пишет заново. Ручные модели и `cells/0_0.json` не трогаются.

## Действующая БД

Новый выпуск добавляет модели в каталог, но не экземпляры в уже инициализированный мир.
После сборки, остановки мира и `pnpm world:migrate`:

```sh
make map-export FILE=output/base.json
pnpm world:boxes:expansion -- --layout output/base.json --out output/edited.json
make map-patch BASE=output/base.json EDITED=output/edited.json PATCH=output/boxes.patch.json
make map-check PATCH=output/boxes.patch.json && make map-apply PATCH=output/boxes.patch.json
```

Режим `--layout` добавляет отсутствующие в экспорте коробки с высотой из `seedY`;
существующие строки не меняет.
