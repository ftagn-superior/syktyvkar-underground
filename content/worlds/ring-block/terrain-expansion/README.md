# Расширение поверхности ring-block

От кольца (X=Z=0): запад 1500 м, восток 2000 м, север и юг по 850 м.
Размер — 3500 × 1700 м, площадь — 5,95 км². Восток соответствует +X, север −Z.
Новые участки содержат только основание; дома, деревья, дороги и вода не импортируются.
Прежние покрытия, объекты, точки появления и предметы сохраняются.

## Источник и точность

Новая поверхность получена из [GEDTM30 v1.2](https://zenodo.org/records/18887460),
OpenGeoHub, CC BY 4.0. Использован официальный COG EPSG:3857 с `scale=1`
и вертикальной системой EGM2008. Это модель земли с номинальным разрешением 30 м
(около 36,4 м на местности здесь). Шаг игровой сетки 4 м задаёт интерполяцию,
а не точность исходной съёмки.

Высоты переводятся сеткой [NGA / PROJ EGM2008](https://cdn.proj.org/us_nga_egm08_25.tif):
`Y = H_GEDTM + N_геоида − 124`. На участке N≈4,93…5,10 м.
Все образцы источников валидны; пропуски не заменяются выдуманными высотами.
Сохраняются URL, SHA-256 обрезок, версия исходной городской сетки и параметры
обработки в `source.json` и `provenance.json`.

Внутри старого прямоугольника X −269…331, Z −745…131 побитно по значениям
сохранены все 33 220 высот `terrain-candidate/full-grid-ready.json`, включая
авторские площадки. Их источник — ArcticDEM Mosaic v4.1, PGC / University of
Minnesota, снимки Maxar, CC BY 4.0, [DOI](https://doi.org/10.7910/DVN/3VDC4W).
Снаружи расхождение высоты ближайшей точки старой границы с GEDTM плавно
затухает на 200 м. Это явно заданный игровой переход, а не геодезическая коррекция
источника. Максимальная поправка снаружи — 10,634 м.

Сетка 877 × 427 сохраняет старую фазу: начало (−1501, −853), шаг 4 м.
Крайние узлы выходят за мир менее чем на один шаг. Графика и физика обрезаются
строго по заданным границам, наружные стенки сохраняются. Поверхность имеет Y
от −45,317 до 22,073 м, нижняя сторона основания — −50 м, нижняя граница мира
−55 м. Публикация содержит 392 ячейки по 125 м с частичной южной строкой.

## Воспроизведение

Обычный `pnpm world:build` читает готовый `grid.json` через
`../terrain-release.json`; сеть, Python и сохранённая БД ему не нужны.

Для повторной подготовки исходных высот и выпуска:

```sh
uv run tools/expand-ring-terrain.py
uv run tools/expand-ring-terrain.py --check
node --import tsx tools/build-ring-terrain-expansion.ts --apply
pnpm world:build
```

Python читает только ограниченные окна двух публичных COG и кеширует их в
`output/ring-terrain-expansion/`. TypeScript сначала собирает отдельный
`candidate-world`, проверяет неизменность всех старых узлов и `seedVersion`,
затем с `--apply` обновляет канонический дескриптор. Без `--apply` дескриптор
сохраняется только в `output/`. Ни одна команда не изменяет БД или production.

Проверка готовой геометрии и Havok требует сохранённого исходного выпуска:

```sh
node --import tsx tests/ring-terrain-expansion.ts <новый-выпуск> <прежний-выпуск>
node --import tsx tests/ring-terrain-expansion-browser.ts <новый-выпуск>
```

Геометрическая проверка сохраняет точность узлов отдельно от приближённых
запросов Havok (допуск 2 см). Браузерный стенд проверяет обычный рендерер,
подгрузку и локальную физику, но не заменяет сетевую игру или длительный замер FPS.
