# Документация

Художественное направление следующей переработки ассетов: [визуальный стиль и главный референс](art-style-guide.md). Гайд описывает целевой вид; готовность реализации проверяется отдельно в игре.

Объём сенсорной доработки — в [плане MVP](plans/touch-controls-mvp.md), фактические проверки и открытая ручная мобильная приёмка — в [отчёте](../reports/touch-controls-mvp.md).

Управление с геймпада в Edge на Xbox Series X|S реализовано по [плану MVP](plans/gamepad-controls-mvp.md): два стика, бег, лобби, ограниченное меню и восстановление ввода. Автоматические результаты и открытая аппаратная приёмка — в [отчёте](../reports/gamepad-controls-mvp.md). Проверка на Xbox проводится в production после слияния PR и запуска сервера из `main`, по обычному адресу игры.

Ядро размещения статики реализовано по [плану MVP](plans/static-placement-core-mvp.md): `/motherlode`, одна модель скамейки, сохранение и общая переподготовка клиентов. Проверки и ограничения описаны в [отчёте](../reports/static-placement-core-mvp.md); `/vilievna` теперь удаляет самостоятельные экземпляры, включая исходные здания; см. [памятку карты](map-model-guide.md). Эта поставка ещё не развёрнута в production.

Каталог размещения через `/motherlode` реализован по [плану](plans/motherlode-placement-catalog.md): поиск, категории, 3D-превью и выбор одной из 22 типовых моделей. Проверки, измерения и открытая ручная приёмка описаны в [отчёте](../reports/motherlode-placement-catalog.md). В production этот этап пока не развёрнут.

Типовая библиотека и instancing реализованы по [плану](plans/static-asset-library-and-instancing.md): выбранные категории используют 22 ассета, заборы собраны из двух типов секций, существующий мир мигрирован. Результаты проверок, замеры и сведения о миграции приведены в [отчёте поставки](static-asset-library-report.md).

Границы минимального игрового MVP описаны в [концепции режима «От первого лица»](plans/first-person-mode.md): обзор с фиксированным наклоном, перспектива из глаз, прогулка и чат с согласованным сетевым разворотом персонажа. Режим реализован в рабочей ветке; фактические проверки и открытая ручная приёмка описаны в [отчёте](../reports/first-person-mode.md).

Возвращение авторизованного игрока в сохранённое место реализовано по [плану первой версии](plans/player-position-persistence-mvp.md): позиция аккаунта в мире сохраняется в PostgreSQL, проверяется сервером и при локальном отказе заменяется обычным спавном. Результаты проверок и открытая ручная приёмка в городе — в [отчёте](../reports/player-position-persistence-mvp.md).

При изменении поведения обновляйте соответствующий рабочий документ. Версии сверяйте с `packages/contracts/src/index.ts` и `apps/server/src/migrations.ts`, команды — с `package.json` и `Makefile`. Результаты прогона сохраняйте в отчёте с версией и окружением.
