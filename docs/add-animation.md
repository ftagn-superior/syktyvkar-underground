# Добавить анимацию

Обычный жест — процедурный косметический клип `humanoid-v1`, работающий на всех скинах.
Для локтей, коленей и поз на земле используйте версионированный `humanoid-v2` ниже.
Генератор готовит согласованные файлы; UI и сервер берут их из реестров автоматически.
Новые игровые анимации добавляются отдельной задачей: пример ниже не входит в поставляемые 15 клипов.

## Подготовка

Нужны Node.js ≥24 и pnpm 12.18.0 (`package.json`, `.node-version`), зависимости из lockfile:

```sh
pnpm install --frozen-lockfile
pnpm animations:check
```

Без установленного pnpm можно использовать `npx --yes pnpm@12.18.0` вместо `pnpm`.
Команды запускаются из корня репозитория, без production-БД и без запущенного сервера.

## Полный пример

```sh
pnpm animations:add -- --id salute --label "Отдать честь" --category "Общение" --mode upperBody --cooldown-ms 1000 --period-ms 1800
```

Команда сначала проверяет нынешнюю коллекцию и все параметры. При успехе:

1. В `content/animations/catalog.json` появляется запись:

   ```json
   {
     "id": "salute",
     "label": "Отдать честь",
     "category": "Общение",
     "mode": "upperBody",
     "cooldownMs": 1000,
     "rig": "humanoid-v1",
     "seated": "preserve-seat"
   }
   ```

2. Создаётся `apps/client/src/rendering/avatars/clips/salute.ts`. Это **рабочая заготовка жеста**;
   автор меняет позу, пока она не выражает нужное движение:

   ```ts
   import { type AnimationClip, rightArm, cycle } from './types';

   const periodMs = 1800;
   export const clip: AnimationClip = {
     rig: 'humanoid-v1',
     periodMs,
     mask: rightArm,
     sample(pose, ms) {
       const phase = cycle(ms, periodMs);
       pose.rightArm = -0.18;
       pose.rightArmYaw = 0.12 * Math.sin(phase);
       pose.rightArmRoll = 2.5 + 0.2 * Math.sin(phase);
     },
   };
   ```

3. Обновляются `packages/contracts/src/animation-catalog.generated.ts` и
   `apps/client/src/rendering/avatars/animation-clips.generated.ts`: литеральные ID,
   типизированная регистрация и отпечаток совместимого выпуска. Их не редактируют вручную.

4. Повторно проверяются весь каталог и выборки поз. При ошибке запись и новые файлы откатываются;
   существующий ID/файл не перезаписывается. `.authoring.lock` защищает одновременные команды записи.
   Если процесс был принудительно остановлен, перед удалением оставшегося lock убедитесь, что команда
   больше не работает, проверьте diff и выполните sync/check; файловый откат не защищает от аварии ОС.

После любой правки манифеста, клипа или `clips/types.ts`:

```sh
pnpm exec prettier --write content/animations/catalog.json apps/client/src/rendering/avatars/clips/salute.ts
pnpm animations:sync
pnpm animations:check
pnpm check
```

Форматируйте исходники **до sync**: отпечаток учитывает их байты. `check` никогда не чинит реестры
молча; он сообщает ID/путь/причину и подсказывает `animations:sync`, если индекс устарел.
Для ручного добавления сделайте шаги 1–2 самостоятельно и запустите sync/check. Лишний файл без
метаданных, метаданные без файла и неправильная регистрация считаются ошибкой.

## Данные, единицы и ограничения

| Поле/параметр             | Правило                                                                                                                |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| id                        | Уникальный стабильный ID, 1–48 ASCII-символов, `[a-z][a-z0-9]*(?:-[a-z0-9]+)*`. Не переиспользовать для другого смысла |
| label                     | Непустая подпись до 80 символов, без внешних пробелов и управляющих символов                                           |
| category                  | Такая же строка до 40 символов. «Все» зарезервировано. Порядок элементов задаёт массив манифеста                       |
| cooldownMs                | Целое число 1..30000 **миллисекунд**, по умолчанию 1000; антифлуд может увеличить паузу                                |
| mode                      | `upperBody` — жест на ходу; `fullBody` — старт только в покое при наличии опоры                                        |
| rig / seated              | `humanoid-v1` / `preserve-seat` для прежних жестов; v2 явно задаёт опору, возможности коляски и reduced motion               |
| periodMs в клипе          | Конечное число 100..60000 мс, по умолчанию 1800; период движения, а не время жизни сетевого показа                     |
| sample(pose, ms, reduced) | Абсолютное прошедшее время в мс; чистый расчёт без Date.now, накопления delta, таймеров, DOM, сцен и физики            |

Для **v1** `AvatarPose` находится в `locomotion.ts`. Повороты — **радианы**, локально относительно модели.
`leftArm/rightArm` — поворот плеча вокруг X, `*Yaw` — Y, `*Roll` — Z;
`leftLeg/rightLeg` — бедро X, `leftLegRoll/rightLegRoll` — бедро Z;
`lean` — наклон корпуса X, `roll` — Z, `lift` — доля высоты персонажа.
Для v1 валидатор ограничивает углы модулем π, lift — 0,1; каналы v2 в маске v1 запрещены. Он проверяет несколько фаз, большой elapsed,
обе настройки reduced motion, повтор позы через periodMs, запись каждого masked-канала, отсутствие записи вне маски и NaN.
Это выборочная проверка, не математическое доказательство для любого времени или качества движения.

Маски из `clips/types.ts`: `rightArm` — 3 канала; `arms` — 6; `fullBody` — руки, бёдра X,
lean/roll/lift. Можно объявить более узкую собственную маску, но она должна быть непустой,
без повторов и из каналов `AvatarPose`. UpperBody разрешает только каналы рук.
`facingOffset` управляется аниматором и запрещён клипам. Все поля маски записываются на **каждом**
вызове: рабочая поза переиспользуется, пропуск поля способен перенести состояние другого клипа.

При `reduced=true` сохраняйте различимость жеста, уменьшайте вторичные lean/roll/lift;
увеличение их абсолютной амплитуды относительно обычного режима отклоняется валидатором.
Например, `pose.roll = 0.08 * Math.sin(phase) * (reduced ? 0.2 : 1)`.
Генератор fullBody содержит такой пример. Маска и reduced-поведение проверяются автоматически.

Сетевой показ циклический и бессрочный в покое. Первое фактическое горизонтальное движение
быстрее 0,08 м/с устанавливает один срок **+5 секунд**; остановка не продлевает его. После cooldown
разрешена замена, включая этот отсчёт. FullBody нельзя начать при принятом вводе даже у стены;
сам безрезультатный ввод не завершает уже начатый показ. Опора, pause, respawn и disconnect
сохраняют общие правила. Переходы — 150 мс, задаются аниматором. Для новых ground-поз движение отменяет позу сразу, без скольжения и пятисекундного таймера. Файлы ассетов для таких клипов
не нужны. Экспорт AnimationGroup, GLB, root motion, произвольный импорт суставов, one-shot или игровое действие
не подключаются этим генератором и требуют отдельного решения.

## Все скины и сидячий вариант

Список берётся из `AVATAR_SKINS`, сейчас 8 вариантов. Для v1 `preserve-seat` — обязательное явное согласие
на существующую адаптацию `AvatarRig`: у `bear-wheelchair` бёдра неподвижны, lift=0, lean ×0,4,
roll ×0,3; движение рук сохраняется. Физическая капсула и посадка не меняются, шаги не звучат.
Полнотелесное движение становится сидячим жестом. Если смысл нового клипа обязательно требует
движения ног, согласуйте содержательный сидячий вариант отдельно; не ослабляйте политику посадки.

`animation-skins.test.ts` автоматически проверяет каждый ID на каждом реальном каркасе в NullEngine,
обе настройки reduced motion, конечность матриц, неизменность корня, посадку и освобождение ресурсов.
Эта матрица не определяет художественную выразительность, пересечения одежды и качество на GPU:
автор осматривает свой клип на всех скинах в предпросмотре и проверяет его у второго клиента.

## Предпросмотр и проверка в игре

Соберите и запустите локальную игру по README (для обычного сервера нужны миграции и тестовая БД).
Войдите, нажмите F в настольном обзоре. Поиск учитывает ID, название, категорию, режим и все слова
запроса; категории видны с переносом. 1–9 назначаются первым девяти результатам **после обоих
фильтров**, и не перехватываются из поля поиска. Enter в поиске переводит фокус на первый результат.
Клик карточки/цифра запускает сетевую анимацию, остальные доступны через Tab и скролл.

Раскройте «Предпросмотр на персонаже». Выберите клип и любой скин, сравните «Уменьшить движение»,
поверните персонажа мышью. Фокус карточки тоже выбирает клип для просмотра. Это одна локальная сцена:
она не отправляет requestAnimation, не расходует cooldown и уничтожается при закрытии панели. При кратком ожидании синхронизации локальный просмотр остаётся открыт, а сетевые кнопки недоступны.
В первом лице, touch и gamepad каталог новых анимаций пока недоступен; узкий desktop не является
подтверждением сенсорной поддержки.

```sh
pnpm exec playwright install chromium
pnpm exec vitest run tests/animation-authoring.test.ts apps/client/src/rendering/avatars/character-animator.test.ts apps/client/src/rendering/avatars/animation-skins.test.ts apps/client/src/rendering/avatars/avatar-view.test.ts apps/client/src/ui/animation-search.test.ts apps/client/src/network/session-version.test.ts
pnpm build
# Экспортируйте SU_TEST_DATABASE_URL к отдельной тестовой PostgreSQL с правом CREATE SCHEMA.
pnpm exec vitest run tests/integration/animations.test.ts tests/integration/server.test.ts
pnpm test:animations:browser
# Быстрая повторная проверка поиска, предпросмотра и размеров, без сетевого перебора всех клипов:

```

Прямые команды выше не читают `.env` автоматически; не подставляйте production-подключение.
Без `SU_TEST_DATABASE_URL` интеграционные тесты пропускаются, браузерный сценарий не получит
изолированную БД. Для регрессии смежной механики — `pnpm test:reactions:browser`; для общего
набора — `pnpm test` с тестовой БД. После изменения цены семплирования дополнительно измерьте
`pnpm test:avatars:profile`: короткий SwiftShader-профиль не подтверждает FPS целевого устройства.

Проверьте выбор/поиск/категорию/цифры, idle и ходьбу, fullBody в покое, замену после cooldown,
срок после движения, потерю опоры, второго наблюдателя, reduced motion и все скины. Приложите
скриншоты нового клипа, результаты команд, ревизию и ограничения стенда.

## Совместимый выпуск

`ANIMATION_CATALOG_VERSION` генерируется как SHA-256 канонических метаданных, имён и байтов клипов
и общего `clips/types.ts`, с версией алгоритма **v2**. В отпечаток также входят исходники каркаса, геометрического разделения, позы, аниматора, AvatarView, скинов и общий контракт (точный список — `animationContractFiles` в `tools/animations.ts`). Смена ID, позы, маски, периода и форматирование
меняют отпечаток; ручной счётчик ID не требуется. Исходники общего контракта при этом **не импортируют
рендерер**: сервер получает только готовые литералы и строку хеша.

`/api/world` публикует `catalogVersions.animations`. Общий контракт S-29 —
`ContentCatalogVersions` и `matchingCatalogVersions` из `packages/contracts/src/content-catalogs.ts`;
проверяется точный набор ключей и значений всех подключённых коллекций. Клиент проверяет карту до
ресурсов/входа, при обновлении публикации и восстановлении; запрос join отправляет собственную
`CLIENT_CATALOG_VERSIONS` из `apps/client/src/presentation/catalog-versions.ts`. Сервер передаёт одну
карту из `apps/server/src/index.ts` в discovery и комнату. Он отклоняет отсутствующий/неравный
отпечаток как `VERSION_MISMATCH` даже при равном PROTOCOL_VERSION.
Нет неявного согласия играть на подмножестве ID. Уже открытым вкладкам нужен reload. Изменение
самой сетевой схемы по-прежнему требует отдельной политики PROTOCOL_VERSION.

Текущий протокол 25 объединяет команды чата, `/speed`, автобусы, LOD/HLOD и формат мира v6 с
обязательной картой совместимости. Карта содержит **оба** ключа `reactions` и `animations`. Вкладки v25 только
с реакциями тоже получают отказ: неполная карта не проходит проверку даже при одинаковом номере.
Обычное добавление анимации меняет её отпечаток; ещё раз повышать протокол ради нового ID не нужно.

Коммитите JSON, модуль и оба индекса вместе; собирайте и выпускайте клиент/сервер из одной ревизии.
S-53 меняет алгоритм отпечатка с v1 на v2: прежние клиенты получают `VERSION_MISMATCH`, даже если каталог всё ещё содержит только 15 старых ID. Номер протокола 25 сохранён: поля запросов и репликации не изменились, новая семантика согласуется точной картой каталогов. Общая механика опоры описана в контракте v2; при её дальнейшей смене пересмотрите алгоритм хеша или протокол. Файлы avatars/ и skins/ автоматически входят в `animationContractFiles`; для вспомогательного кода в других каталогах проверьте включение в отпечаток.
Соглашение S-29: команды `<коллекция>:add|sync|check`, локальные валидаторы, общие contracts без
движка, генерируемые артефакты под контролем Git. Для реакций/предметов не используйте отпечаток
анимаций вместо собственного контракта. `reaction-release.ts` предоставляет версию и URL реакций,
а общий `catalog-versions.ts` собирает обе встроенные версии. Сервер проверяет комплект SVG и
манифест реакций, сохраняет снимок ассетов и выдаёт версионированные URL; добавление анимации
не изменяет этот выпуск. Сохраните оба ключа при изменении общих карт, `reactions:check` и
`animations:check` в `pnpm check`. При изменении допуска повторите проверки обеих коллекций.
Порядок выпуска — согласованная сборка приложения, не отдельная публикация JSON или реестра.

## Humanoid-v2: локти, колени, сидение, лежание и колесо

Полный технический контракт и карта исходных ограничений: [Каркас v2](animation-rig-v2.md).
Не меняйте существующим ID rig на v2 без отдельной проверки вида. Старые 15 клипов остаются v1.
Все векторы позы локальны к персонажу: +X вправо, +Y вверх, +Z вперёд; углы в радианах.
Нулевые новые каналы сохраняют исходную геометрию и прежние точки вращения.

| Каналы | Граница | Смысл |
| --- | --- | --- |
| `leftElbow/rightElbow` | −2,7..0 | локальный X дочернего локтя; отрицательное значение сгибает предплечье вперёд |
| `leftKnee/rightKnee` | 0..2,7 | локальный X дочернего колена; положительное значение сгибает голень назад |
| `rootPitch/rootYaw/rootRoll` | −2π..2π | ориентация всего визуального тела вокруг X/Y/Z, порядок Y·X·Z |
| `rootX/rootZ` | −0,15..0,15 высоты | локальное боковое/продольное смещение внутри занятого пространства |
| `rootY` | 0..0,15 высоты | зазор над опорой после автоматического размещения по нижней точке модели |

Корневые каналы разрешены только с `support: ground`; это косметические преобразования,
которые не записываются в сетевую позицию, капсулу, камеру или точку взаимодействия.
`articulatedArms` добавляет локти к прежним каналам рук, `articulatedBody` включает все конечности,
наклоны и корень. UpperBody и любой seated-вариант используют только articulatedArms или её подмаску.
Для ground обязательна полная articulatedBody: базовая походка не должна проникать в низкую позу.

Полный пример через генератор (выполняйте в отдельной задаче на контент или временной копии):

```sh
pnpm animations:add -- --id ground-rest --label "Отдых на земле" --category "Позы" --mode fullBody --rig humanoid-v2 --support ground --seated variant --seated-message "Отдельный вариант: спокойная посадка в коляске." --reduced-motion static --reduced-motion-label "Статичное сидение." --period-ms 4000
```

Результат имеет явные `rig`, `support`, `seated`, `seatedMessage`, `reducedMotion`,
`reducedMotionLabel` в JSON и соответствующий `seated` sampler в модуле. Редактируйте его так:

```ts
import {
  type AnimationClip, articulatedBody, articulatedArms, neutralArticulatedPose,
} from './types';

export const clip: AnimationClip = {
  rig: 'humanoid-v2',
  periodMs: 4000,
  mask: articulatedBody,
  sample(pose) {
    neutralArticulatedPose(pose); // записывает ровно все поля articulatedBody
    pose.leftLeg = pose.rightLeg = -2.1;
    pose.leftKnee = pose.rightKnee = 1.1;
    pose.leftElbow = pose.rightElbow = -0.6;
    // Для лежания: вместо сгиба ног rootPitch = -Math.PI / 2.
    // Для лежания на боку: rootRoll = -Math.PI / 2 и умеренный сгиб коленей.
  },
  seated: {
    mask: articulatedArms,
    sample(pose) {
      for (const channel of articulatedArms) pose[channel] = 0;
      pose.leftElbow = pose.rightElbow = -0.6;
    },
  },
};
```

Для лежания и колеса задайте `seated: unavailable` с понятным `seatedMessage`, удалите `clip.seated`.
UI отключит действие и объяснит причину, предпросмотр скроет неподдерживаемую модель; сервер
отклонит поддельный запрос. Для сидения вариант действительно сохраняет раму, ноги и посадку.
`preserve-seat` в v2 допускается только для масок рук, с capsule-опорой.

Колесо выражается циклическим `rootRoll = cycle(ms % periodMs, periodMs)` с поднятыми руками и
разведёнными ногами. `rootX/rootZ` можно менять внутри их границ. В reduced motion показывайте
**постоянную** подготовительную позу без вращения и назовите её в `reducedMotionLabel`.
Готовые технические образцы всех четырёх действий — `tests/fixtures/animation-rig/`.
Они не зарегистрированы в поставляемой коллекции; это материал для проверки и начала работы S-34.

Ground-клип требует неподвижного игрока, статичной почти горизонтальной опоры и свободного квадрата
со стороной 1,6 высоты и высотой 1,3 высоты персонажа. Сервер проверяет коллизии объёма и 3×3 луча
опоры при запуске и во время показа. Стены, другие игроки, предметы, узкий край и подвижная опора
мешают запуску; UI сообщает «Нужно свободное ровное место». Это намеренно консервативный допуск.
Капсула остаётся вертикальной: сидение и лежание не дают пролезать под препятствиями.
Принятый ввод движения отменяет ground до шага физики, фактическая скорость тоже отменяет его.
При движении, падении и несовместимом скине история ground не смешивается обратно, чтобы поза
не скользила. Замена в покое и обычный выход смешиваются за 150 мс; опора учитывается и в переходе.

Валидатор проверяет обе версии/политики, все маски/записи, диапазоны, конечность, периодичность,
статичность reduced-альтернативы и реальные вершины каждого поддерживаемого скина в NullEngine,
в том числе промежуточные веса входа/выхода. Пробы конечны: осмотр на GPU обязателен.
Нельзя убрать маску, увеличить bounds или объявить вариант без sampler ради прохождения проверки.

Браузерный сценарий создаёт временную копию, добавляет четыре фикстуры **генератором**, пересобирает
клиент/сервер, проверяет независимого наблюдателя, все скины, reduced motion, отказ у стены,
отмену/замену/смену скина/reconnect и старую карту версий. PNG и JSON пишет в
`output/playwright/rig-v2/`; копию удаляет после завершения. `--interactive-review` держит локальный
стенд до Enter для ручного осмотра в том же запуске. Клипы в основном каталоге не появляются.
