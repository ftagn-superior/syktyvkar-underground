# Соглашения расширяемых коллекций S-29

У каждой коллекции своя предметная схема и одна каноническая инструкция. Стабильный ID не зависит от подписи или позиции в меню. Метаданные не дублируются вручную на клиенте и сервере; игровые состояния не смешиваются с авторским форматом. Общие контракты остаются без DOM, файловой системы и зависимостей от движка.

Для команд принят рисунок `<collection>:check`, `<collection>:add`, `test:<collection>:browser`. Реализованы [реакции](reactions.md): `reactions:add`, `reactions:check`, `test:reactions`; и [анимации](add-animation.md): `animations:add`, `animations:sync`, `animations:check`. Для анимаций `sync` обновляет сгенерированные реестры после изменения позы, профильные тесты перечислены в инструкции. Обе проверки входят в обычный `pnpm check`. Добавление сначала проверяет вход и коллизии, создаёт согласованные файлы, проверяет итог и печатает дальнейшие шаги. Новые пользовательские элементы не входят побочно в PR инструментов.

## Совместимость выпусков

S-30 вводит `ContentCatalogVersions` и `matchingCatalogVersions` в `packages/contracts`. `WorldInfo.catalogVersions` и поле JOIN — карта `{ reactions: "sha256", ... }`. Сервер и клиент требуют точного совпадения набора ключей и значений; отсутствующая версия не означает совместимость. Свой ключ следующая коллекция добавляет в обе стороны. Текущий **протокол 25, мир v6** включает команды чата, `/speed`, автобусы, LOD/HLOD и обе версии коллекций. Старые вкладки до v25 требуют обновления; одинаковый номер без одинаковой карты недостаточен. Дальнейшее пополнение реакций само по себе не требует очередного повышения протокола: меняется отпечаток.

Обе карты содержат `reactions` и `animations`: серверная в `apps/server/src/index.ts`, клиентская `CLIENT_CATALOG_VERSIONS` в `apps/client/src/presentation/catalog-versions.ts`. Версия реакций и их URL остаются в `reaction-release.ts`; анимации получают отпечаток из сгенерированных contracts. Серверная сборка проверяет байты SVG против встроенного SHA-256; браузерные URL содержат версию. Для SDK/нагрузочного клиента передавайте `catalogVersions` из `/api/world` вместе с остальными параметрами входа; такой клиент проверяет сетевую механику, а не наличие собственного визуального реестра. Браузер передаёт свою встроенную карту, а не копирует серверную. Диагностический отчёт использует ту же полную клиентскую карту.

## Порядок PR

Порядок интеграции — **S-30 / PR #65 → обновление базы S-31 / PR #64 → S-31**. S-30 уже входит в базу S-31 вместе с автобусами и LOD/HLOD. S-31 сохраняет v25 и дополняет карту анимациями; вкладка v25 только с `reactions` явно отклоняется. Отдельное поле `animationCatalogVersion` не заменяет общую карту. Следующая коллекция добавляет ключ в обе карты, сохраняет проверки существующих коллекций и повторяет их тесты допуска. S-32 может поставлять собственные инструменты независимо, пока не меняет карту. Новый ID существующей коллекции сам по себе не требует повышения протокола: меняется отпечаток.

Общие места возможных конфликтов: `package.json` (объединить команды/проверки), `AGENTS.md` и `docs/README.md` (сохранить ссылки всех коллекций), `contracts/src/index.ts` и `session.ts`, серверный discovery/JOIN, клиентский preflight/recovery и документация UI. S-30 не меняет общий `ui/catalog-shortcuts.ts`, чтобы сохранять существующее поведение анимаций. Разные коллекции не обязаны иметь одинаковые эффекты, срок жизни, физику или хранение.

## Проверка и отложенные направления

Критерий обычного добавления: автор по одной инструкции получает согласованные файлы, понятные отказы и проверяемый выпуск без скрытых UI/серверных регистраций. Быстрые проверки работают с временным содержимым; сохранность прежних ID/ассетов проверяется отдельно. Сетевые/браузерные сценарии используют выделенную тестовую БД; пропуск SQL или эмуляция устройства явно отмечаются.

Внешний сервис контента, универсальный движок коллекций, виртуализация и загрузка тяжёлых ресурсов по потребности не являются зависимостями авторинга. Для них сначала нужны реальные измерения большого набора на целевом устройстве и самостоятельное решение.
