# План реализации большой карты v0.2

12 ноября 2026 года. Статус: **L0–L5 / LM-01–14 выполнены**; LM-15 / L6 остаётся для итоговой аппаратной и пользовательской приёмки. L5 закрыл функциональные LM-AC01–08/10 и оба 30-минутных программных прогона. L4 добавил серверную видимость 80/100 м, фильтрованные первые снимки/переподключения и очистку клиентских прокси. Измерения и решения L0–L5 — в [отчёте](../reports/large-map.md). Основание — согласованная [спецификация следующего этапа](large-map-streaming.md): карта 2 × 2 км, до 8 игроков, один серверный мир, клиентская загрузка участков и сетевая область интереса. Числа L0–L6 относятся к этому этапу и не заменяют историю M0–M4 первой технодемо.

## Поставка и порядок

Результат — запускаемая `streaming-lab`, обновлённый малый `physics-lab`, общие контракты, диагностика, автоматические сценарии и отчёт. Сервер первой поставки держит всю упрощённую статику. Активация серверных участков рассматривается отдельной задачей при подтверждённой необходимости.

| Этап                            | Запускаемый/проверяемый результат                                                                                | Условие завершения                                                                                 |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| L0 Измерения и проверки подхода | Исходный замер, фиксированный профиль содержимого, минимальные проверки StateView и физического жизненного цикла | Закрыты LM-T01–LM-T04; параметры и команды воспроизводимы                                          |
| L1 Пространственные данные      | Повторяемый пакет мира с настоящими ячейками, заголовком и версиями                                              | LM-AC01; сервер собирает полную геометрию без дублей; контракты для следующих этапов зафиксированы |
| L2 Клиентские участки           | Загрузка, показ и освобождение статики в изолированном браузерном сценарии                                       | Локальные части LM-AC02/03/06/08; обычная смена ячейки сохраняет мир предсказания                  |
| L3 Вход и согласование движения | Два браузера входят, перемещаются по карте, возвращаются и восстанавливаются                                     | LM-AC03/04/06/07; сервер пока может отправлять все девять динамических сущностей                   |

Критическая последовательность: L0 → L1 → L2 → L3 → L4 → L5 → L6. После L1 можно независимо готовить серверный индекс/схемы L4 и инструменты L5; их интеграция ждёт готового жизненного цикла L3. Это зависимости работ, а не назначение исполнителей или требование многопоточного выполнения разработки. Оценки сроков определяются после L0 по измерениям.

Эксперименты завершаются проверяемыми выводами в `reports/large-map.md`; тяжёлые данные — в `output/large-map/`. Эти пути создаются реализацией. Существующая документация библиотек не заменяет проверку установленной версии. L0 использует временные минимальные данные и не требует готового нового сборщика. Временные обходы удаляются при появлении штатных контрактов; закрытие проверки не означает выполнения всех функциональных требований.

Для LM-04 предлагаются параметры `SU_WORLD_SOURCE` для сборки и `SU_WORLD_DIRECTORY` для запуска; они реализованы и описаны в README. По умолчанию сохраняется малый `physics-lab`. HTTP-префикс формируется по выбранному `worldId`; одновременно обслуживается один активный мир. `streaming-lab` включается явно, без копирования серверного приложения.

Тестовые точки входа и ускоренная подготовка нужны для помещения участников в удалённые районы без минут ожидания. Они включаются только в отдельной тестовой конфигурации; обычный клиент не выбирает серверные координаты. Сами проверки пересечения границ выполняются настоящим вводом движения.

В сетевом профиле приёмки — RTT 100 мс с jitter ±20 мс; дополнительно RTT 200 мс, потери TCP 1% и краткий обрыв для проверки восстановления и ограниченных очередей. Медленную HTTP-загрузку проверяем отдельно от задержки WebSocket. Оценка коррекций сохраняет число событий и пики до сглаживания.

SDK-клиенты проверяют сервер и сеть; память, графику и потоковую загрузку доказывают браузеры. Команды движения на большом мире получают цели из маршрутов, а не из текущего малого радиуса 13 м. Сценарий crowd имеет известную тестовую цель независимо от того, виден ли ящик конкретному клиенту. Ожидаемая видимость вычисляется по серверным координатам и истории порогов, а не равенством числа локальных игроков общей занятости.

## Проверки и артефакты передачи

При изменении контрактов/физики выполняются существующие `pnpm check`, `pnpm test`, `pnpm build` и затронутые физические/сетевые браузерные сценарии. В рамках LM-14 добавляется отдельная команда `pnpm test:streaming:browser`, которая сама поднимает изолированный сервер `streaming-lab` и сохраняет свидетельства. До реализации этой команды она не считается доступной.

Проверка сборки включает оба выбранных мира и запуск из артефакта без исходников. Для протокола подготовки обновляются тестовые клиенты всех затронутых сценариев; прежние проверки не отключаются ради перехода на частичный снимок. Длительные и аппаратные проверки выполняются после функциональных, повторяются при изменениях, влияющих на их результат.

| Путь, создаваемый реализацией              | Содержание                                                                                              |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| `content/worlds/streaming-lab` и генератор | Воспроизводимый профиль 2 × 2 км и маршруты; генерируемые тяжёлые файлы — в dist/output                 |
| `reports/large-map.md`                     | Статус LM-T/LM-AC, оборудование, версии, бюджеты, ограничения, сравнение исходного и итогового профилей |
| `output/large-map/`                        | HTTP/WS-трафик, метрики, исходные распределения, скриншоты/видеозаписи и профили памяти                 |
| README и инструкция моделей/карты          | Реально существующие команды выбора мира, настройки сетки и ограничения подготовленного содержимого     |

Передачу завершают после выполнения всех LM-AC01–10, обоих длительных прогонов и аппаратных бюджетов. Если целевого GPU или серверного профиля нет, отчёт прямо оставляет соответствующую проверку открытой; функциональную готовность можно показать отдельно. Установка значений в таблице плана не является результатом замера.

## Условия продолжения после v0.2

Если бюджеты не выполняются, сохраняются воспроизведение и профиль причины. Сначала исправляются выявленные ресурсы, порядок работы, кэши и локальные обходы. При подтверждённой стоимости всей серверной статики оформляется отдельная доработка управления активными участками по правилам спецификации; до исправления и повторного прогона приёмка остаётся открытой.

Увеличение лимита игроков, импорт города, серверные worker-процессы, замораживание/сохранение динамических тел и внешнее размещение не добавляются как скрытые зависимости. План не создаёт задач во внешнем трекере и не выполняет выпуск на сервер.
