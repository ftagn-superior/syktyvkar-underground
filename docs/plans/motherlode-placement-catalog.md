# Каталог размещения через `/motherlode`

Дата: 13 ноября 2026 года. Статус: **реализован в рабочей ветке; итоговые проверки и измерения — в [отчёте](../../reports/motherlode-placement-catalog.md); production не подтверждён**.
Основа исследования — `8d7d83b`, ветка `map`. Формат метаданных и производный
каталог моделей уже реализованы и опубликованы в `origin/map`.

Владелец подтвердил вход через `/motherlode` и состав первого выпуска:
**22 типовые модели** — деревья, кусты, скамейка, фонари, светофор, столбик и
секции забора. Остальные решения ниже задают предлагаемый целевой контракт
реализации. Документ не является подтверждением поставки или развёртывания.

## 1. Результат этапа

Вошедший через Telegram пользователь отправляет `/motherlode`, находит модель
в каталоге, рассматривает её, выбирает место и сохраняет один новый статичный
объект. Другие клиенты получают то же размещение; перезапуск сервера сохраняет
его. Пользователь не вводит технический ID и не пользуется SQL или консолью.

Основной путь:

```text
/motherlode
  → проверка доступа сервером
  → каталог: категории, поиск, карточки
  → выбор модели и её 3D-превью
  → «Разместить»
  → ghost на карте, положение и поворот
  → «Поставить»
  → подтверждение записи и общая подготовка окружения
```

После одного успешного размещения инструмент закрывается. Для следующего
пользователь снова открывает `/motherlode`; выбранная категория и строка поиска
сохраняются в памяти вкладки. Автоматического повторения последней модели нет.

Успех этапа — весь этот путь работает для всех 22 разрешённых моделей, включая
деревья без GLB, на небольшом тестовом мире и настоящем `ring-block`.

## 5. Авторские данные и источники истины

Добавить необязательное авторское поле `placementPolicy` в `WorldSource`:

```json
"placementPolicy": "placement.json"
```

Оно указывает на файл относительно `content/worlds/<worldId>/world.json` и не
попадает в игровой заголовок, физическую проекцию или идентичность размещений.
Для `ring-block` создать `content/worlds/ring-block/placement.json`:

```ts
type WorldPlacementPolicySource = {
  formatVersion: 1;
  assetIds: string[];
};
```

Массив содержит приведённые выше 22 ID без повторов. Названий, категорий, размеров,
путей к GLB и копий коллайдеров в нём нет. Тестовый мир вправе иметь меньший
явный список; отсутствие политики означает, что новые игровые размещения отключены.

Сборщик проверяет политику и записывает рядом с производным каталогом:

```ts
type WorldPlacementPolicy = {
  formatVersion: 1;
  worldId: string;
  assetReleaseVersion: string;
  assetIds: string[];
}; // dist/model-catalogs/<worldId>/placement-policy.json
```

Проверки политики обязательны:

1. ID уникален, зарегистрирован в основном каталоге и присутствует в manifest.
2. Авторская карточка отображается в единственный runtime ID, совпадающий с её ID.
3. Модель не является `ground` и не принадлежит фиксированному слою выпуска.
4. Физический профиль — ровно один корректный box-коллайдер; габариты конечны.
5. Графическое представление — поддержанный статичный GLB либо актуальный `parts.tree`.
6. Все выбранные ресурсы принадлежат принятому `assetReleaseVersion`.

Некорректную явно заданную политику нельзя молча сокращать. Ошибка сборки должна
назвать мир, ID и причину. При запуске несогласованные артефакты явно включённого
каталога останавливают готовность сервера до исправления. Мир без политики может
работать с отключённой командой.

Отключение новых размещений не отключает replay уже отправленных операций:
проверка истории остаётся доступной действующему авторизованному аккаунту.

Обновить `world:catalog:check`: проверять и политику, если она задана в исходнике.
Режим `--sources` проверяет структуру и регистрацию; проверка после сборки — также
привязку к выпуску и физический/графический профиль. Не повышать версию основного
формата метаданных только ради отдельной политики размещения.

## 6. Каталог, который получает клиент

При запуске сервера сформировать один проверенный `PlacementCatalog` из:

- полного `WorldModelCatalog`;
- `WorldPlacementPolicy`;
- принятого manifest и геометрии мира;
- общих параметров размещения `groundY=0`, `yawSteps=24`.

```ts
type PlacementCatalog = {
  formatVersion: 1;
  worldId: string;
  assetReleaseVersion: string;
  modelCatalogVersion: string;
  placementCatalogVersion: string;
  groundY: 0;
  yawSteps: 24;
  categories: Record<string, { name: string }>;
  models: Array<{
    assetId: string;
    metadata: WorldModelMetadata;
  }>;
};

type PlacementCatalogReference = {
  assetReleaseVersion: string;
  modelCatalogVersion: string;
  placementCatalogVersion: string;
  url: string;
};
```

`modelCatalogVersion` — значение `catalogVersion` полного каталога. В палитру
входят только категории выбранных моделей. Габариты, версии моделей и пути к
ресурсам клиент берёт из своего проверенного `manifest.assets[assetId]`.

`placementCatalogVersion` — SHA-256 канонического JSON всего `PlacementCatalog`
без самого этого поля. Модели упорядочены по `assetId`, теги и ключи категорий
канонизированы. Пользовательская сортировка по русским названиям выполняется после
проверки хеша и не меняет идентичность. Изменение списка, метаданных, параметров
размещения или выпуска меняет версию палитры.

### Публикация и чтение

Сервер хранит снимок палитры в памяти процесса. Явный маршрут:

```text
GET|HEAD /worlds/<worldId>/placement-catalogs/<placementCatalogVersion>.json
```

Раздаётся только проверенный снимок по точному пути текущего процесса; остальные
хеши и методы не открывают файловую систему. Ответ — канонический JSON, тип
`application/json`, `Cache-Control: public, max-age=31536000, immutable`.
Маршрут зарегистрировать до общего `app.use(worldPath, ...)`, который иначе
перехватит запрос и вернёт 404.
Палитра не содержит персональных данных; её чтение публично, как чтение моделей.
Право открыть инструмент и выполнить запись проверяется отдельно по аккаунту.

`WorldInfo` дополнить необязательным `placementCatalog: PlacementCatalogReference`.
Это источник актуальной ссылки для восстановления и обновления клиента. Успешный
ответ `/motherlode` использует ту же ссылку из одного серверного сервиса:

```ts
type StaticPlacementEffect = {
  kind: 'staticPlacement';
  catalog: PlacementCatalogReference;
  publication: WorldPublicationInfo;
};
```

Фиксированный `effect.assetId` удаляется. Параметры плоскости и поворота приходят
в проверенном каталоге. Команда не создаёт одноразовый токен или серверную сессию
редактора: конечное полномочие определяется аккаунтом и действующей политикой.

До показа кнопки размещения клиент проверяет формат, хеш, версии ссылки и тела,
мир, соответствие `assetReleaseVersion` активной публикации, категории и все ID
по manifest. Ссылки на модели разрешаются только проверенным ресурсным загрузчиком.
При 404 или смене поколения допускается одно обновление `/api/world`; дальнейший
сбой показывает ошибку с явной кнопкой повтора, без бесконечного цикла запросов.

Палитра не включается в manifest, `mapVersion`, `assetReleaseVersion` или
`layoutHash`. Новая расстановка не пересоздаёт её. В этой поставке изменения
метаданных/политики применяются сборкой и перезапуском; горячая замена не вводится.

Чтение опубликованного полного каталога и проверку его хеша перенести из
`tools/world-build/src/model-catalog.ts` в Node-часть `@su/world-release` и
переиспользовать в сборщике и сервере. Сервер не импортирует инструменты сборки.
Типы, канонические проекции и проверки JSON остаются в `@su/contracts` без Node API.

Папку полных каталогов передавать серверу явно: штатный запуск использует
`dist/model-catalogs/<worldId>/`; тесты с `buildWorld(source, output)` передают
`<output>/model-catalog/`. Не сканировать соседние папки в поисках подходящей версии.

## 7. Интерфейс каталога

Использовать текущие DOM/CSS, токены дневной/ночной темы, рамки и кнопки из
[интерфейса клиента](../ui.md). Один основной акцент — кнопка «Разместить».
Новый дизайн-системный слой и отдельное приложение не нужны.

Схема широкого окна:

```text
┌ Размещение объектов                            Закрыть × ┐
│ Поиск по названию или описанию…                          │
│ Все · Растительность · Городское оборудование · …         │
│ Найдено 22 модели                                        │
├──────────────────────────┬───────────────────────────────┤
│ Берёза, малый размер     │ Берёза, малый размер           │
│ Берёза, средний размер   │                               │
│ …                        │       [одно 3D-превью]        │
│ Скамейка парковая        │                               │
│ …                        │ Описание из метаданных        │
│                          │ Габариты из bounds, м         │
│                          │ [Повернуть] [Сбросить вид]    │
│                          │           [Разместить]        │
└──────────────────────────┴───────────────────────────────┘
```

Карточка содержит имя и иконку категории. Выбор карточки открывает сведения и
реальную 3D-модель справа, но не запускает ghost. Индивидуальные изображения всех
карточек не обязательны в этом выпуске. Если после использования 22 названий
окажется недостаточно для поиска, миниатюры станут отдельным следующим улучшением.

### Поиск, категории и сортировка

- «Все» и только категории доступного набора; подписи из общего справочника.
- Строка ищет по `name`, `description`, тегам и техническому ID; последний полезен
  разработчику, но не заменяет пользовательское имя в карточке.
- Нормализация: регистр, крайние/повторные пробелы, `ё → е`. Все введённые слова
  должны встретиться в объединённом поисковом тексте; выбранная категория действует одновременно.
- Теги остаются авторскими. Для поиска русских слов вроде «дерево» использовать
  названия/описания и небольшой общий словарь поисковых синонимов контролируемых
  тегов (`tree`, `bush`, `bench`, `fence`, `lamp`, размеры), не менять сами ID тегов.
- Порядок карточек: русское название, затем `assetId` для одинаковых имён.
- Показать количество результатов и явное «Сбросить поиск» при пустом результате.
- Первоначально ни одна модель не выбрана; кнопка размещения недоступна.
- Если выбранная карточка исчезла из-за поиска/категории, снять выбор и закрыть её
  превью. При возвращении из ghost сохранить выбор, поиск и категорию.

Все 22 записи фильтруются на клиенте. Пагинация, серверный полнотекстовый поиск,
индекс поисковой БД и удалённые запросы при каждом символе не нужны.

### Управление и доступность

Окно модальное, с понятным заголовком, `aria-modal`, управлением фокусом и возвратом
фокуса в игровой canvas при закрытии. При открытии фокус получает поиск.
`Tab` обходит доступные контролы внутри окна; `Enter`/`Space` выбирает карточку,
но не подтверждает установку. `Esc` закрывает каталог без записи. Щелчок по
подложке ничего не ставит и не закрывает инструмент неожиданно.

Результаты и ошибки доступны через `role=status`/`aria-live` без покадровых
объявлений. Выбор обозначен текстом/состоянием контрола, а не только цветом.
Номера 1–9, если переиспользуется `CatalogShortcuts`, действуют только вне
поисковой строки и выбирают карточку. Они не запускают размещение.

Пока каталог открыт, персонаж стоит, движение и вращение игровой камеры выключены.
Глобальные WASD, A/D и колесо не обрабатываются игрой поверх ввода или 3D-превью.
На узком настольном окне список и сведения располагаются вертикально с прокруткой;
кнопки и закрытие остаются достижимыми с клавиатуры. Проверить 1280×720, 960×675
и узкое настольное окно 640×720, обе темы и масштаб интерфейса 200%.

## 8. Превью модели и ghost

### Одна графическая основа

Выделить создание одиночного визуального экземпляра с явным владельцем ресурсов:

```ts
createModelVisual(scene, descriptor, verifiedResources, purpose);
// purpose: 'catalog-preview' | 'placement-ghost'
// результат: корень, bounds, управление показом, dispose()
```

Это целевой интерфейс, точное имя допускается уточнить при реализации. Он должен
использовать существующий `loadBuildingContainer` для GLB и общий шаблон/профиль
дерева из `tree-geometry`, `tree-material` и `parts.tree` для деревьев. Нельзя
создавать второй упрощённый рецепт берёзы или выпускать резервные GLB деревьев.

В каталоге сохраняются геометрия, цвета, материалы и запечённый AO модели.
В ghost применяется нейтральная полупрозрачная подача. Дерево должно поддерживать
оба режима независимо от отсутствия `modelFile`; ветка `parts.tree` выбирается
по проверенным данным, а не по строковому префиксу ID.

Иерархические трансформации GLB и параметры дерева сохраняют реальный масштаб и
локальный pivot. Одиночное превью не добавляется в batches и физику игрового мира.
После подтверждения объект проходит обычный путь thin instances/деревьев.

### Сцена каталога

Использовать одну небольшую отдельную сцену/canvas по образцу `CharacterPreview`.
В каждый момент в ней одна выбранная модель; камера подбирает расстояние по
полным bounds с учётом пропорций canvas. Высокий фонарь и короткая секция забора
должны помещаться целиком. Размеры в подписи вычисляются из bounds в метрах.

Вращение мышью и доступные кнопки меняют только обзор превью. Кнопка сброса
возвращает начальный ракурс. Автоматическое вращение не требуется; при
`prefers-reduced-motion` не добавлять анимацию. Освещение фиксировано, тема меняет
фон и окружение панели, но не перекрашивает авторскую модель.

Рендерить только пока превью видно; ограничить canvas примерно 320 CSS px и
плотность не выше 1,5, без дорогих теней. При скрытой вкладке/закрытии останавливать
рендер и освобождать сцену. Не создавать отдельный engine на каждую карточку.

### Асинхронность и освобождение

Одновременно загружается одна выбранная модель. Новый выбор отменяет предыдущий
запрос через `AbortController`; generation защищает от позднего результата.
Поздно созданные контейнеры/материалы/геометрии освобождаются, даже если загрузчик
завершился после отмены. Общие bytes можно переиспользовать через существующий
ограниченный кеш ресурсов, но UI не держит 22 загруженных 3D-контейнера.
Отмена потребителя UI освобождает только его владение ресурсом и не должна
прерывать общий запрос, которым ещё пользуется игровой загрузчик.

После «Разместить» сцена каталога закрывается, создаётся один ghost в игровой
сцене. До готовности ghost подтверждение выключено. Ошибка загрузки не создаёт
запрос записи; пользователь может повторить загрузку или вернуться в каталог.

Клик по карточке или «Разместить» не должен пройти сквозь DOM в canvas и поставить
объект. Первое подтверждение требует нового pointerdown либо нового нажатия
клавиши после перехода. Текущую защиту `freshPointer`/`freshConfirmKey` сохранить.

## 9. Машина состояний инструмента

| Состояние         | Что видит пользователь                                        | Допустимые переходы                                                          |
| ----------------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `closed`          | Обычный HUD                                                   | Успешная команда → `catalog-loading`                                         |
| `catalog-loading` | Окно и «Загружаем каталог…»                                   | Готовность → `browsing`; ошибка → `catalog-error`; Esc → `closed`            |
| `catalog-error`   | Причина, «Повторить», закрытие                                | Повтор → `catalog-loading`; Esc → `closed`                                   |
| `browsing`        | Поиск, карточки, необязательная выбранная модель              | Выбор → загрузка/показ превью; «Разместить» при готовности → `ghost-loading` |
| `ghost-loading`   | Панель размещения, подтверждение выключено                    | Готовность → `placing`; ошибка → возврат к выбору/повтор; Esc → `closed`     |
| `placing`         | Ghost и имя модели, A/D, «Поставить», «Другая модель»         | Новое подтверждение → `pending`; другая модель → `browsing`; Esc → `closed`  |
| `pending`         | «Сохраняем размещение…», повтор/смена модели/отмена выключены | Успех → `waiting-world`; окончательная ошибка → соответствующий экран        |
| `waiting-world`   | Обычный индикатор общей подготовки окружения                  | Готовность → `closed`; сбой → существующий сценарий восстановления           |

Превью выбранной карточки имеет собственные `loading/ready/error`, не подменяя
состояние каталога. Ошибка одной модели не скрывает весь список.

Открытие из первого лица возвращает обзор и освобождает Pointer Lock. Обратный
переход в первое лицо запрещён до закрытия каталога/ghost. Автоматически возвращать
Pointer Lock после закрытия не нужно.

Инвентарь, чат и другие игровые панели до отправки закрывают инструмент по
существующим правилам взаимного исключения. Повторная команда при открытом
каталоге активирует его, не создавая второе окно или вторую сцену. При `pending`
новая команда не начинает другое размещение.

Потеря фокуса скрывает активную позу ghost, сбрасывает удержанные клавиши и требует
свежего действия после возврата. Выход, потеря графики, смена аккаунта и touch
освобождают неподтверждённые сцены. Отправленная операция принадлежит
`PersistentOperation`, а не жизненному циклу DOM или ghost.

## 10. Запрос и серверная последовательность

Целевой запрос:

```ts
type PlaceStaticRequest = {
  operationId: string; // UUID, постоянен при транспортных повторах
  worldEpoch: string;
  assetReleaseVersion: string;
  placementCatalogVersion: string;
  expectedLayoutRevision: number;
  assetId: string;
  position: { x: number; z: number };
  yawStep: number; // 0..23
};
```

Парсер проверяет точный набор полей, форматы, конечность чисел, диапазон поворота.
Клиент не передаёт Y, quaternion, scale, коллайдеры, автора, `enabled`, `entityId`
или `sourceRef`. Сервер сам строит экземпляр с `Y=0`, нормализованным поворотом,
`placed_<operationId>` и выбранным проверенным `assetId`.

Внутри существующей последовательной очереди:

1. Проверить действующую авторизацию и владельца аккаунта.
2. Проверить успешный replay по `operationId`, аккаунту, `assetId` и канонической
   позе. Эта проверка предшествует устаревшим версиям каталога и расстановки.
3. Для новой записи проверить готовность мира, текущий epoch, выпуск, версию
   палитры и ожидаемую ревизию. Затем проверить включение ID в явную политику.
4. Проверить частоту и бюджеты, поставить существующую паузу и завершить flush.
5. Взять свежий snapshot, повторно проверить ревизию, геометрию и сохранность.
6. Подготовить кандидат публикации до записи. Ошибки подготовки не меняют БД.
7. Повторно проверить авторизацию, выполнить существующую транзакцию `createGame`.
8. Применить ровно один экземпляр, активировать подготовленную публикацию и
   инициировать существующий барьер подготовки клиентов.

Фабрика экземпляра, `replayGame`, `createGame` и сравнение in-flight запросов
используют выбранный ID, без скрытой константы скамейки. Нельзя сравнивать только
позицию: тот же UUID с другим ассетом возвращает `OPERATION_CONFLICT`.
Заголовки версий остаются предусловиями новой записи, а не её replay-идентичностью.

Сохраняются `source='game'`, существующая история и `instance_revision`. Для
неопределённого COMMIT, ошибки применения после COMMIT и восстановления после
перезапуска сохраняются правила текущего ядра. Новая таблица всех результатов
операций и параллельная система публикации не вводятся.

## 11. Геометрия, основание и лимиты

### Физическая проверка

Переиспользовать `checkStaticPlacement(instance, asset)` для одного box с локальным
смещением и поворотом. Физическая форма, визуальные bounds и quaternion берутся
из принятого выпуска. Профиль проверяется при сборке политики и старте сервера,
а не обнаруживается только после нажатия «Поставить».

Сохранить проверки границ, реальных пересечений с миром/персонажами/предметами,
внутреннего объёма закрытых mesh, точек появления, текущих и сохранённых поз
предметов. Погрешность контакта с поверхностью остаётся 5 мм. Кроны деревьев могут
визуально пересекаться: физическую занятость определяет ствол, а не AABB кроны.
Визуальные bounds при этом целиком должны оставаться в границах мира.

Не заменять box дерева на крону или забор на произвольный масштаб. Две соседние
секции могут касаться концами без проникновения; автоматическая привязка концов
и построение линии ограды в этом этапе отсутствуют.

Проверку плоского основания на `Y=0` выделить из проверки скамейки и использовать
на уровне всего инструмента. Поддержка наклонного или неоднородного рельефа не
добавляется. При неподходящем мире команда явно недоступна.

### Устранение лимита 2048

Текущее сравнение `buildings.length + entities.length >= 2048` удалить из live-пути.
Оно уже меньше существующего города и смешивает редактируемые объекты с плитками
земли и граничными примитивами.

Зафиксировать общий `MAX_EDITABLE_STATIC_INSTANCES = 10_000`, согласованный с
`WorldLayoutSnapshot`. Считать все строки snapshot, включая отключённые: их
активация и сохранение тоже должны оставаться допустимыми. Фиксированный слой
не расходует этот лимит. Использовать общий контракт вместо новой локальной цифры.

Отдельно сохраняются лимиты публикации и загрузчика: до 10 000 ссылок размещений
в ячейке, ограничение размера ячейки 512 КиБ и клиентский бюджет 16 384 уникальных
статичных объектов. Плитки и границы учитываются в этих технических бюджетах.
До COMMIT проверить, что кандидат укладывается в них. Превышение возвращает
`CONTENT_LIMIT`, а не ошибку хранилища; лимиты форматов ради каталога не увеличивать.

Для детерминированного превышения бюджета издатель должен возвращать различимую
типизированную ошибку. Не определять `CONTENT_LIMIT` по тексту исключения и не
смешивать её с ошибкой записи файлов или недоступностью БД.

Сам факт допуска до 10 000 строк не означает приемлемую производительность любой
раскладки. Проверки рабочего города и наблюдение паузы обязательны.

## 12. Ошибки, конкуренция и версии

Добавить две причины результата: `CATALOG_CHANGED`, `ASSET_NOT_ALLOWED`.
Остальные причины сохраняют существующую семантику.

| Причина/событие                          | Поведение                                                                                                          |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Ошибка загрузки/хеша каталога            | До записи показать «Не удалось загрузить каталог», повтор и закрытие                                               |
| Ошибка загрузки модели                   | Отключить «Разместить»/«Поставить», оставить повтор или другую модель                                              |
| `AUTH_REQUIRED`                          | Закрыть неподтверждённый инструмент, предложить вход                                                               |
| `OUT_OF_BOUNDS`, `BLOCKED`               | Окончательно завершить этот запрос; сохранить выбранную модель и вернуть ghost для нового явного подтверждения     |
| `RATE_LIMITED`                           | Показать ограничение частоты; автоматически новую запись не создавать                                              |
| `LAYOUT_CHANGED`                         | Обновить публикацию, затем разрешить новое явное подтверждение с новым UUID и актуальной ревизией                  |
| `CATALOG_CHANGED`                        | Завершить запрос, обновить discovery/каталог и вернуть выбор; не переотправлять другой набор полей под тем же UUID |
| `ASSET_NOT_ALLOWED`                      | Убрать устаревший выбор и обновить палитру; показать понятную причину                                              |
| `STALE_WORLD`, `VERSION_MISMATCH`        | Пройти существующее обновление мира и повторное открытие инструмента                                               |
| `CONTENT_LIMIT`                          | Сохранение не произошло; показать «Достигнут лимит объектов», без автоматического повтора                          |
| `WORLD_NOT_READY`, `STORAGE_UNAVAILABLE` | Сохранить pending и существующий отложенный повтор того же неизменённого запроса                                   |
| `OPERATION_CONFLICT`                     | Не повторять автоматически; показать ошибку операции, не генерировать замену UUID молча                            |

Транспортный повтор сохраняет все поля запроса. Новое явное подтверждение после
окончательной ошибки создаёт новый UUID. В клиенте одновременно одна durable
static-операция; до её разрешения нельзя выбрать модель для второй записи.

Если другой игрок изменил расстановку при открытом каталоге, версия палитры
сохраняется. Во время подготовки мира кнопки действий недоступны; после барьера
поиск и выбор могут остаться. Ревизия захватывается при подтверждении позиции,
а не при открытии окна. Клиент не заменяет поля уже отправленного запроса.

Не включать новую палитру в SQL-идентичность сохранённых размещений. Изменение
названия или списка доступных новых моделей не переписывает историю, не удаляет
поставленные объекты и не требует миграции существующих ссылок на ассеты.

## 13. Обновление протокола и старые pending-операции

Клиент и сервер выпускаются согласованно с новой версией протокола — на текущей
основе это 14, перед реализацией проверить следующий свободный номер. Старый
сетевой формат с неявной скамейкой не принимает новые записи. Схема БД 6 и форматы
мира/ячеек сохраняются, если реализация не обнаружит отдельной необходимой причины.

Важна локальная совместимость: `PersistentOperation` хранит старые запросы под
`su:static-operation:<accountId>`. Нельзя просто заменить парсер и молча потерять
сохранённый UUID после потерянного подтверждения.

Предусмотреть узкий преобразователь именно старой записи v13:

1. Проверить старую структуру; сохранить `operationId`, epoch, выпуск, ревизию и позу.
2. Явно добавить прежний ID скамейки и `placementCatalogVersion`, состоящую из
   64 нулей. Это зарезервированная версия **только для reconciliation**.
3. Сервер после авторизации выполняет обычный поиск успешного replay. При совпадении
   подтверждает исходный экземпляр, даже если скамейка больше не разрешена для новых записей.
4. Если успешной операции нет, нулевая версия всегда возвращает окончательный
   `CATALOG_CHANGED` и никогда не доходит до записи. Пользователь открывает актуальный каталог.

Реальная палитра не может использовать нулевую версию. Не подменять старые
предусловия текущими и не превращать восстановление старой записи в новую установку.
Этот небольшой адаптер не поддерживает старый сетевой протокол или несколько UI.
Удалять его можно только при отдельно согласованном прекращении поддержки старых
локальных pending-записей; календарная дата сама по себе не доказывает их отсутствие.

Добавить тест потерянного ответа COMMIT с обновлением клиента, успешного replay
после перезапуска, запрета новой записи из старого pending и изоляции аккаунтов.

| 3. Обобщённая запись                | Размещение выбранного ID через существующую очередь | Все 22 box-профиля, replay с выбранной моделью, лимиты текущего города, rollback           |
| 4. Визуальная основа                | GLB и дерево для превью/ghost                       | Совпадение силуэта/масштаба, отмена поздних загрузок, освобождение ресурсов                |
| 5. Каталог и переходы               | Полный UX от команды до подтверждения               | Поиск, категории, клавиатура, отсутствие click-through, смена камеры/панелей               |
| 6. Сохранённые pending и интеграция | Восстановление после переподключения и обновления   | Тот же UUID и объект, межаккаунтная изоляция, старый pending не создаёт новый объект       |
| 7. Приёмка и документация           | Небольшой мир и настоящий город, отчёт              | Функциональные проверки, измеренная пауза, сборка и регрессии                              |

Сначала зафиксировать типы и физический профиль. Разработку сцены превью и
серверного HTTP после этого можно вести независимо; это не основание менять
согласованный контракт в двух местах. Объединять компоненты до окончательной
приёмки, а не считать отдельные unit-тесты подтверждением всего сценария.

## 16. Проверки и критерии готовности

### Контракты, сборка и HTTP

- Политика города содержит ровно согласованные 22 ID; производная палитра содержит те же модели и четыре категории.
- Неизвестный ID, ground, фиксированный слой, несколько runtime-ресурсов, неподдержанный коллайдер и повреждённые версии отклоняются с причиной.
- Проверены хеш, повреждение body/reference, неправильный мир/выпуск и 404 старого процесса; нет бесконечного обновления каталога.
- Правка только метаданных/политики меняет версию палитры и сохраняет версии геометрии, физики, seed и расстановки.
- Новая live-расстановка сохраняет ту же палитру, а HTTP продолжает отдавать проверенный снимок.

### Физика и SQL на отдельной тестовой БД

- Для каждого из 22 реальных ассетов найдено свободное место, установка сохраняет именно выбранный `asset_id`.
- Проверены повёрнутые bounds, контакт с землёй, занятое место, персонаж, предмет, внутренний объём здания, точки появления и safePose предметов.
- Деревья проверяются по физике ствола; касание соседних секций без проникновения допустимо.
- Реальный город с числом объектов больше 2048 принимает свободное размещение; край лимита 10 000, отключённые строки и технические лимиты проверяются раздельно.
- Повтор одного UUID не добавляет объект; другой ассет или поза под тем же UUID дают конфликт.
- Отказ до COMMIT сохраняет строки, ревизии, историю, предметы и активную публикацию; неопределённый COMMIT восстанавливает тот же результат.
- После смены политики прежний успешный запрос можно подтвердить, но новую запрещённую установку выполнить нельзя.

### Клиент и браузер

- `/motherlode` открывает каталог, а не скамейку; гостю установка недоступна даже при ручной отправке запроса.
- Поиск, категории, одинаковые названия, пустой результат и сброс проверены; UI не показывает неразрешённые модели.
- Все 22 модели имеют настоящее превью и ghost; отдельно проверены ель, берёза, высокий фонарь и обе секции забора.
- Два клиента видят один сохранённый объект; restart сохраняет выбранную модель и его ID.
- Быстрый выбор A → B, закрытие во время загрузки, поздний GLB, потеря графики и повторное открытие не оставляют сцен и ghost.
- Клик/Enter из каталога не ставит объект; свежий ввод после потери фокуса работает; текст поиска не двигает персонажа.
- Проверены дневная/ночная темы, указанные размеры окна, масштаб 200%, клавиатурное прохождение и reduced motion.
- Истёкшая авторизация, отзыв сессии, смена аккаунта, reconnect, потерянный ответ, ошибка ресурса и конкурентное размещение имеют описанные исходы.
- Вход из первого лица переключает обзор; инвентарь и сенсорный режим сохраняют правила взаимного исключения.

### Полный город и стоимость операции

Повторить двухклиентный сценарий на `ring-block` с актуальной политикой и ресурсами.
Зафиксировать подготовку публикации, общую паузу, время готовности каждого клиента,
число файлов/байт и ошибки браузера. Отдельно измерить открытие каталога и загрузку
первого GLB/дерева; открытие без выбора не должно загружать все 22 модели.

Историческая пауза около 15 с в [отчёте ядра](../../reports/static-placement-core-mvp.md)
относится к прежнему миру и программному renderer. Её нельзя выдавать за новый
замер или обещание удобства. Барьер остаётся 15 с; увеличение timeout клиента
не является способом приёмки. Исключение клиента при штатном новом сценарии
фиксируется как незакрытая проблема поставки.

Оптимизацию общего издателя или бесшовное обновление мира не включать скрыто.
Если текущий путь не проходит городской сценарий, явно зафиксировать блокер и
согласовать отдельный объём оптимизации. Программный GPU подтверждает функциональность,
а целевая производительность проверяется на реальном оборудовании.

Команды: `pnpm world:catalog:check --sources`, `pnpm build`,
`pnpm world:catalog:check`, `pnpm check`, `pnpm test` с тестовым
`SU_TEST_DATABASE_URL`, обновлённый `pnpm test:static-placement:browser`,
городской вариант `SU_STATIC_PLACEMENT_WORLD=ring-block`, а также регрессии
GLB/деревьев, инвентаря, чата, первого лица и потоковой загрузки по затронутому пути.
Тесты БД не считать пройденными, если они пропущены из-за отсутствия настройки.

## 17. Поставка и документация

Перед реализацией повторно проверить ветку, текущие контракты и состояние мира.
Изменение не требует переписывания ранее поставленных скамеек или других
размещений. Остановить сервер для штатной сборки ресурсов, выпустить клиент и
сервер согласованно, подтвердить версии и выполнить обычную проверку сохранённого
мира. Если изменены только каталог/политика, не запускать миграцию геометрии как
обязательный шаг без фактического изменения её идентичности.

На откате сохранить возможность подтвердить уже зафиксированные операции;
не удалять строки новых объектов. Все выбранные ассеты уже присутствуют в прежнем
выпуске моделей. Откат приложения отдельно проверяется против текущих хешей
сохранённого мира; при несовместимости использовать штатный проверенный выпуск,
а не принудительно подменять версии в БД.

После реализации обновить:

- `docs/world-model-catalog.md` — отдельная политика и HTTP-палитра;
- `docs/map-model-guide.md`, `docs/ui.md`, помощь и README — новый путь `/motherlode`;
- `docs/testing.md` — команды и условия приёмки;
- `docs/operations.md` — размещение артефактов, согласованное обновление и откат;
- `docs/PROJECT_CONTEXT.md` и оглавление — фактический статус этапа;
- новый отчёт в `reports/` — коммит, стенд, выполненные проверки и измерения.

Исторический план одной скамейки и его замеры сохраняются как история. В отчёте
отдельно отметить реализацию, автоматическую проверку, ручную приёмку и production.
Отправка коммита в origin сама по себе не подтверждает развёртывание.

## 18. Решения и оставшиеся границы

Принято владельцем: точка входа `/motherlode`, назначение — размещение моделей,
первый набор — 22 типовые модели. Существующее правило доступа любого действующего
Telegram-аккаунта сохраняется.

Техническое предложение плана: явная политика мира, производная палитра с отдельной
версией, одно 3D-превью, существующая физика одного box, текущий путь записи и
общая переподготовка. Поддержка всех 226 моделей не является скрытым продолжением
этого задания: она потребует отдельного решения по составу и физическим профилям.

Открыты только проверяемые при реализации риски: фактическая пауза полного города,
поведение одиночного полупрозрачного дерева на поддержанных браузерах и целевая
производительность на GPU. Они не оправдывают молчаливое исключение деревьев,
увеличение сетевого timeout или объявление неполного пути завершённым.
