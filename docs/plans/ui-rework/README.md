## Цель

Интерфейс выглядит как лаунчер, наложенный на игру: почти чёрные панели со срезанными углами, моноширинные клавиши, один и тот же вид днём и ночью. Нужен интерфейс, который принадлежит этому городу: печатная бумага, чернильная рамка, коми-орнамент, брусничный красный, и две темы, которые следуют за игровыми сутками.

## Принятые решения

| Тема | Решение |
| --- | --- |
| Материал | Непрозрачные «бумажные» панели, рамка 2px, жёсткая тень снизу. Без стекла и `backdrop-filter` |
| День и ночь | Две темы: «берёста» днём, «полночь» ночью. Переключение мгновенное на восходе и закате. Плавный переход отклонён |
| Настройка темы | Авто / День / Ночь, хранится у игрока |
| Цвет игрока | Больше не красит интерфейс. Отмечает только самого игрока: персонаж, знак, имя в чате |
| Кнопка `?` | Без цвета. Остаётся входом в управление и настройки |
| Игроки в сети | Иконка людей и число; по щелчку список игроков |
| Часы | Чип со временем мира и иконкой солнца или луны |
| Чат | Внизу слева. Лента последних сообщений видна всегда, поле ввода по умолчанию скрыто: вместо него кнопка чата. `T` раскрывает поле, оно остаётся раскрытым (в том числе после отправки), пока игрок не свернёт его клавишей `Esc` или щелчком по миру. **В макете поле показано всегда — это устарело, верна спецификация.** Позже станет полноценным чатом с историей |
| Реакции и анимации | Две кнопки рядом с кнопкой чата (в раскрытом виде — в строке ввода). Окно с фильтром по категориям и прокруткой, без страниц. У реакций строка «Недавние» |
| Рюкзак | Кнопка справа внизу со счётчиком. Открывает лоток: одна плитка на тип предмета. Стопок, ячеек, разделения и объединения в интерфейсе нет |
| Рюкзак для гостей и касаний | Показываем обоим. Гостю вместо содержимого подсказка «войдите через Telegram» |
| Подсказка подбора | Плашка над предметом с клавишей `Z`, действием и названием |
| Подпись над головой | Без рамки, полупрозрачная подложка, обычное начертание, знак игрока |
| Знак игрока | Одна из девяти простых фигур, выдаётся случайно, не уникальна |
| Кнопки | Выбранная кнопка становится «сквирклом», не кругом. Подписи клавиш бледнее иконок |
| Шрифты | Rubik (заголовки, кнопки) и Golos Text (всё остальное). Unbounded, Manrope и JetBrains Mono уходят |
| Лобби | Персонаж в сцене, карточка-«пропуск», значок «Трудовой славы», один блок вместо десяти закрытых карточек |
| Выбор цвета | Круглые образцы и «свой цвет» с двумя ползунками: оттенок и тон |

## Не входит (бэклог)

- Английская версия интерфейса и переключатель RU / EN. В макете кнопка есть; в реализацию **не берём**, но новые строки не стоит разбрасывать по коду так, чтобы перевод потом стал невозможен.
- Новые названия и значения предустановленных цветов («Морошка», «Брусника» и другие). См. «Ограничения».
- Постоянный знак игрока, привязанный к аккаунту. См. «Открытые вопросы».
- Иконки предметов из настоящих 3D-моделей или в пермском зверином стиле вместо эмодзи.
- Полноценный чат с историей, прокруткой и каналами.
- Анбур как декоративный шрифт на экранах загрузки.

## Ограничения

- **Параллельная работа.** Над проектом одновременно работает второй разработчик. Изменения держим в `apps/client/src/ui/`, `apps/client/src/style.css`, `apps/client/index.html`, `apps/client/src/interaction/`. Общие файлы (`main.ts`, `world-view.ts`, `session.ts`) правим точечно, без попутного форматирования. Перед слиянием сверяемся с `origin/main`.
- **Протокол и контракты не меняем.** `packages/contracts`, сервер и версия протокола остаются как есть. Отсюда два следствия:
  - список предустановленных цветов (`PROFILE_COLORS`, 12 штук) сохраняется; меняется только их вид. «Свой цвет» по-прежнему отдаёт `#RRGGBB`;
  - действия `split`, `merge`, `move` остаются на сервере, клиент их просто не вызывает.
- **Производительность.** Целевая машина — Intel UHD 620. Никаких размытий поверх холста. Смена темы — одно изменение атрибута на корне, без покадровой записи CSS-переменных.
- **Язык.** Тексты интерфейса, документация и комментарии — на русском; идентификаторы и сообщения коммитов — на английском.
- **Доступность не теряем.** В текущем коде есть `aria-*`, возврат фокуса, `prefers-reduced-motion`, режим `forced-colors`, цели 44px для касаний. Всё это должно пережить переработку.

## Этапы

Каждый этап — отдельный коммит или небольшой PR, после которого игра работает.

### 1. Токены и чистка

- В `ui/theme.css` завести токены поверхностей и текста для двух тем (значения в `design-spec.md`), выбор темы через `data-ui-theme` на `<html>`.
- Убрать из `style.css` около ста жёстко заданных цветов и весь старый «скруглённый» слой, который `hud.css` потом переопределяет.
- Заменить примитивы со срезанными углами (`.su-facet`, `.su-corner`, `.su-gem`, `.su-hex`, `clip-path` на кнопках) новыми: панель, кнопка, чип, лента орнамента.
- Подключить Rubik и Golos Text в `index.html`, убрать три старых семейства.
- `applyAccent()` в `ui/theme.ts` больше не красит интерфейс. Цвет игрока остаётся одной переменной для элементов «про игрока».
- Исправить баги из `current-state.md`.

Готово, когда: в CSS нет цветов вне токенов (кроме самих токенов и SVG персонажей), обе темы включаются вручную сменой атрибута, все существующие окна читаемы в обеих.

### 2. Тема по игровым суткам

- Чистая функция «высота солнца + текущая тема → тема» с гистерезисом у горизонта, с тестом. Высоту даёт `sunPosition(hour).y` из `rendering/day-cycle.ts`.
- `WorldView` уже знает текущий час (`world-view.ts`, вызов `lighting.setTimeOfDay` в кадре). Нужен способ отдать наружу час или высоту солнца; тему выставлять только при смене значения.
- Настройка Авто / День / Ночь в панели управления, ключ `localStorage` по образцу существующих (`su:render-quality:v1`).
- Лобби живёт поверх того же мира, поэтому использует ту же тему.
- Убрать или привязать ко времени постоянную тёмную виньетку (`.vignette` в `style.css`).

Готово, когда: `/time 12` и `/time 1` меняют тему без перезагрузки, принудительная настройка переживает перезагрузку страницы.

### 3. Раскладка HUD

- Вверху слева `?`; вверху справа чип часов и чип игроков со списком.
- Внизу слева блок чата: лента, кнопки чата, реакций и анимаций. Поле ввода скрыто и раскрывается по `T` или кнопке чата; состояние «раскрыт» держится до явного закрытия (см. `design-spec.md`, раздел 5). Сейчас `ui/chat.ts` закрывает поле после отправки — это меняется; закрытие по `Esc` остаётся, добавляется закрытие щелчком по миру.
- Внизу справа док: вид от первого лица, рюкзак.
- Панель управления (`ui/help.ts`) остаётся для клавиш и настроек; строки-кнопки чата, реакций, анимаций и инвентаря из неё уходят.
- Лента чата собирается на клиенте из наблюдаемых изменений `chatText` / `chatSequence` у игроков, протокол не меняется. Хранить последние 5 строк, старые бледнеют.
- Всплывающее уведомление (`#notice`) переезжает наверх по центру.

Готово, когда: все действия доступны без открытия панели управления, горячие клавиши `T`, `R`, `F`, `X`, `V`, `H`, `Esc` работают как раньше.

### 4. Реакции и анимации

- Одно окно над строкой чата. Фильтры — категории из каталогов в `packages/contracts` (`reactions.ts`, `animations.ts`), плюс «Все».
- Прокручиваемая область фиксированной высоты. У реакций сверху строка «Недавние» (4 штуки, хранить локально).
- Клавиши 1–9: сейчас `ui/catalog-shortcuts.ts` привязывает их к первым девяти пунктам. Для реакций предлагается привязать к «Недавним», для анимаций оставить как есть. **Уточнить у владельца** перед изменением.
- Сохранить состояния ожидания и перезарядки (`reactionStatus()`, `animationStatus()`), которые есть сейчас.

### 5. Рюкзак

- `ui/inventory.ts` (524 строки) заменяется лотком: группировка `session.inventory.slots` по `typeId`, одна плитка на тип с суммарным количеством.
- «Поставить» берёт любой экземпляр этого типа и отправляет прежнее действие `place`. Подбор не меняется.
- Выбор плитки закрывает лоток и включает размещение; подсказка размещения — небольшая плашка наверху вместо широкой панели.
- Гость видит кнопку рюкзака; в лотке вместо плиток подсказка о входе.
- Риск: если у предметов появятся индивидуальные свойства (`InventoryItem.properties`), одной плитки на тип не хватит. Сейчас свойства пустые; при группировке всё же сравнивать и их, чтобы не слить разные предметы.

### 6. Элементы в мире

- Подсказка взаимодействия (`interaction/prompt.ts`, классы `.su-ctx`, `.su-key`).
- Подпись игрока, пузырь чата, стикер реакции (`world-view.ts`, классы `.player-label`, `.player-chat`, `.player-reaction`) и подписи мест (`.landmark-label`).
- Знак игрока: чистая функция «строка → индекс фигуры» с тестом; набор из девяти SVG-фигур.

### 7. Лобби

- Новая раскладка `index.html` + `ui/lobby.css`: шапка со значком, персонаж в сцене, карточка-пропуск, полоса персонажей.
- `ui/color-picker.ts`: круглые образцы и «свой цвет» с ползунками оттенка и тона вместо шестиугольников и конического образца.
- `ui/avatar-picker.ts` и `ui/characters.ts`: доступные персонажи кнопками, закрытые — одной строкой «ещё N появятся с обновлениями».
- Живой предпросмотр (`ui/character-preview.ts`) остаётся как есть, меняется только его обрамление.

### 8. Касания, тесты, документация

## Тесты

Интерфейс покрыт браузерными тестами, которые завязаны на селекторы. Около 30 файлов в `tests/` используют `#join`, `#help-toggle`, `#help-panel`, `.inventory-choice`, `.reaction-choice`, `.animation-choice`, `.su-ctx[aria-keyshortcuts="Z"]`, `#chat-input` и подобные. Общая точка входа — `tests/helpers/hud.ts` (`hudClick` сначала открывает панель управления).

Рекомендация: где возможно, сохранять существующие `id` (`#join`, `#chat-input`, `#inventory-toggle`, `#reactions-toggle`, `#animations-toggle`, `#help-toggle`, `#respawn`, `#leave`), а `hudClick` упростить до прямого щелчка. `tests/browser-items.ts` проверяет разделение и объединение стопок через интерфейс; эти шаги нужно убрать или перевести на прямые команды сессии.

Проверки перед сдачей каждого этапа:

```sh
npx --yes pnpm@12.18.0 check
npx --yes pnpm@12.18.0 test
```

Браузерным тестам нужен PostgreSQL (`SU_TEST_DATABASE_URL`, см. `docs/testing.md`). Для ручной проверки на машине владельца: собрать `node tools/build.mjs`, при изменении мира `node --import tsx tools/world-build/src/index.ts`, поднять БД, выполнить `dist/server/migrate.mjs` и `migrate-world.mjs`, запустить `dist/server/main.mjs`. ## Открытые вопросы

1. **Знак игрока: от чего считать.** Без изменения протокола доступны только реплицируемые поля. Варианты: от `sessionId` (меняется при каждом входе) или от имени и цвета (стабильно, но меняется при переименовании). Постоянный знак аккаунта требует поля в контрактах и согласования со вторым разработчиком. Предложение: начать с имени и цвета.
2. **Список игроков.** Клиент получает динамику только своей области интереса. Нужно проверить, видны ли в состоянии комнаты все игроки или только ближние. Если только ближние, список показывает «рядом», а общее число берётся из сведений о комнате.
3. **Клавиши 1–9 в реакциях:** первые девять или «Недавние».
4. **Размещение касанием.** Текущее размещение ведёт луч от указателя мыши и вращает предмет клавишами. Для касаний нужен свой сценарий (нажатие по миру, кнопки поворота). Можно вынести в отдельную задачу и на первом шаге дать касаниям только подбор и просмотр рюкзака.
5. **Настройка качества «Экономное».** Стекла больше нет, поэтому отдельного режима интерфейса для слабых машин не требуется. Подтвердить, что пружинные анимации не нужно отключать вместе с тенями.

## Как решены открытые вопросы при реализации

Решения временные: их легко поменять, если владелец выберет иначе.

1. **Знак игрока** считается от имени и цвета (`ui/player-sign.ts`), как и предлагалось.
2. **Список игроков.** Игроки реплицируются только в области интереса, поэтому число в чипе берётся из `occupancy` комнаты, а под списком появляется строка «Остальные далеко», если показаны не все.
3. **Клавиши 1–9 в реакциях** оставлены за первыми девятью пунктами *показанного* списка (после фильтра). «Недавние» клавиш не получили. Переключить на «Недавние» — одна строка в `ui/reactions.ts` (`renderList`). **Нужно решение владельца.**
4. **Касания.** Кнопка рюкзака и лоток видны, плитки только для просмотра; подбор — касанием подсказки. Клавиши-ярлыки в режиме касаний не работают, как и раньше. Размещение касанием не сделано.
5. **«Экономное» качество** интерфейс не меняет: размытий больше нет, пружинные анимации не отключаются (их гасит только `prefers-reduced-motion`).

Отступления от спецификации: в плашке размещения предмета есть главная кнопка «Поставить» (как у скамейки), а в раскрытом поле чата — маленькая кнопка отправки внутри поля. Тексты в окне анимаций сокращены до названий; причина недоступности показывается под названием.
