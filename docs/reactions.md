# Добавление реакции

Обычная реакция — метаданные и самостоятельный SVG-стикер. Команда создаёт оба файла, проверяет их и печатает дальнейшие действия. Она не добавляет жест тела, предмет, индивидуальную длительность или отдельный звук. Для таких изменений сначала нужна задача на механику.

Источник истины — `packages/contracts/src/reactions.ts`, массив `REACTIONS`. SVG находятся в `apps/client/public/reactions/`. Меню, серверное разрешение ID, категории, счётчики и общий звук подключаются автоматически. Существующие реакции доступны гостям и аккаунтам в настольном обзоре. Отправка отключена в touch, gamepad и первом лице; чужие реакции продолжают отображаться.

## Подготовка

Из корня репозитория, Node ≥24 (версия проекта в `.node-version`), pnpm 12.18.0:

```sh
pnpm install --frozen-lockfile
pnpm reactions:check
pnpm reactions:add --help
```

Для добавления и быстрых тестов PostgreSQL и браузер не нужны. Для игровой проверки нужны сборка, Chromium и выделенная тестовая PostgreSQL с правом создавать схемы. Используйте `SU_TEST_DATABASE_URL`; не подставляйте production-подключение.

## Входные параметры и правила

| Поле/параметр             | Правило                                                                                                                                                                                                              |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--id` / `id`             | Уникальный стабильный ID, 1–48 символов. Строчная латинская буква в начале, далее строчные буквы/цифры и одиночные дефисы. Пример: `bravo`, `hot-coffee`. ID не переименовывать при изменении подписи.               |
| `--label` / `label`       | 1–48 видимых символов, без крайних пробелов и управляющих/невидимых управляющих символов. Это подпись карточки и `alt` стикера.                                                                                      |
| `--category` / `category` | Точно одна из `Общение`, `Эмоции`, `Занятия`, `Статус`. «Все» — фильтр UI, а не категория. Список определён в `reaction-validation.ts`; новая категория требует явного расширения этого списка и проверки раскладки. |
| `asset`                   | Строго `<id>.svg` с тем же регистром, без каталогов. Команда устанавливает поле сама.                                                                                                                                |
| `--asset`                 | Необязательный путь к готовому рисунку; файл копируется, исходник не изменяется. Без параметра создаётся SVG-заготовка.                                                                                              |
| `--dry-run`               | Полная предварительная проверка без итоговых изменений контентных файлов.                                                                                                                                            |

SVG: UTF-8, размер от 1 до **65 536 байт**, `xmlns="http://www.w3.org/2000/svg"`, `viewBox="0 0 64 64"`, хотя бы один векторный элемент. Бюджет — выбранное правило авторинга, не измеренный аппаратный предел игры. Фон за рисунком прозрачный; проверьте читаемость при 32 px в карточке и 60 px в мире.

Поддерживается статичный поднабор: `svg`, `g`, `path`, `rect`, `circle`, `ellipse`, `line`, `polyline`, `polygon`, `defs`, `linearGradient`, `radialGradient`, `stop`, `clipPath`, `mask`, `use`, `title`, `desc`. Разрешены локальные `href="#id"` и `url(#id)`. Внешние картинки/ссылки, встроенный растр, `style`, скрипты, обработчики событий, анимационные элементы, DOCTYPE/ENTITY и processing instructions не входят в формат. При экспорте из редактора преобразуйте стили в обычные атрибуты `fill`, `stroke` и т. п. XML проверяет настоящий XML-парсер; визуальную пригодность рисунка всё равно проверяет автор.

## Полный пример: «Браво»

Если `bravo` уже существует, выберите другой ID. Сначала можно проверить ввод:

```sh
pnpm reactions:add --id bravo --label "Браво" --category "Общение" --dry-run
```

Затем создать заготовку:

```sh
pnpm reactions:add --id bravo --label "Браво" --category "Общение"
```

Результат — одна запись, дописанная в конец `REACTIONS`, и `apps/client/public/reactions/bravo.svg`:

```ts
{ id: 'bravo', label: 'Браво', category: 'Общение', asset: 'bravo.svg' },
```

Пример полного допустимого рисунка, которым можно заменить заготовку:

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 64 64" fill="none">
  <title>Браво</title>
  <circle cx="32" cy="32" r="27" fill="#68C8ED" stroke="#254B60" stroke-width="2.5"/>
  <path d="m32 12 5 13 14 1-11 9 4 14-12-8-12 8 4-14-11-9 14-1 5-13Z"
    fill="#F3B35A" stroke="#523821" stroke-width="2.5" stroke-linejoin="round"/>
</svg>
```

Если готовый рисунок уже есть, вместо создания заготовки выполните одну команду:

```sh
pnpm reactions:add --id bravo --label "Браво" --category "Общение" --asset ./art/bravo.svg
```

Не выполняйте оба варианта подряд с одинаковым ID. Повторный ID, конфликт файла, недопустимая категория или SVG возвращают ненулевой код с ID/путём. Команда сначала проверяет существующий каталог и весь кандидат, затем создаёт ассет эксклюзивно и заменяет реестр через rename. При обычной ошибке записи изменения откатываются. Одновременные генераторы исключаются `.reactions-add.lock`; не редактируйте реестр вручную во время команды. Если процесс принудительно завершён, изучите PID в lock-файле, убедитесь, что он больше не работает, удалите оставшийся lock и запустите валидатор. Атомарной транзакции между двумя файлами при отключении питания не обещается.

Ручной путь тоже поддерживается: создайте `<id>.svg`, допишите объект из четырёх строковых полей в конец `REACTIONS`, затем выполните проверку. Не нужны дополнительные импорты, HTML-кнопки, switch/case сервера или регистрации сокращений. Добавление в конец сохраняет цифровые позиции прежних первых элементов; цифры после фильтра/поиска вычисляются заново.

## Проверка результата

```sh
pnpm reactions:check
pnpm test:reactions
pnpm check
pnpm build
pnpm exec playwright install chromium
```

Валидатор входит и в `pnpm check`, и в сборку. Он проверяет весь каталог: уникальность/поля/категории, соответствие файлов, отсутствующие/лишние изображения, XML/формат/бюджет SVG. Типичный отказ: `Реакция "bravo" (.../bravo.svg): SVG: ожидается viewBox="0 0 64 64"`.

`pnpm test:reactions` проверяет реальное создание шаблона/импорт SVG/CLI во временных копиях, отказы, отсутствие перезаписи, откат ошибки, сохранение имеющихся записей/ассетов, смену отпечатка, поиск, правила реакций и несовместимые клиенты. Тесты не требуют фиксированного количества записей и не требуют менять их при обычном добавлении.

После сборки установите **тестовый** `SU_TEST_DATABASE_URL` через окружение и выполните:

```sh
pnpm exec vitest run tests/integration/server.test.ts tests/integration/reaction-release-built.test.ts
pnpm test:reactions:browser
```

Сетевая проверка охватывает допуск клиента, версию коллекций и картинки, жизненный цикл, повторные запросы и восстановление. Без `SU_TEST_DATABASE_URL` SQL-набор Vitest пропускается и не подтверждает доставку. Браузерный сценарий требует БД, сам поднимает сервер и проходит все записи каталога в двух гостевых контекстах; результаты/снимки — `output/playwright/reactions/`. По умолчанию он использует `economy` и reduced motion для воспроизводимости на программном GPU; `SU_REACTIONS_QUALITY=standard` выбирает стандартное качество.

Для нового рисунка дополнительно проверьте сами: найдите его по подписи и ID, совместите поиск с категорией, выберите клавиатурой и мышью, убедитесь в одном правильном стикере у наблюдателя, смените ещё видимую реакцию после cooldown, начните движение и проверьте исчезновение. В покое показ бессрочный; базовый cooldown выбора — **1 с**, серия быстрых выборов удлиняет паузу до 30 с; движение запускает **отдельный таймер 5 с**. На 320/390 px и коротком окне проверьте подпись, все категории, Tab и последнюю карточку. В поиске цифры — текст; Enter/ArrowDown переводят фокус к результатам, после этого 1–9 выбирают первые результаты. Esc закрывает панель. Уменьшение движения отключает общее появление/затухание, не изменяя смысл стикера.

## Согласованный выпуск

`reaction-release-built.test.ts` запускает настоящий собранный сервер с копией выпуска и отдельной SQL-схемой: проверяет отказ старому клиенту, несовпадающему манифесту и изменённому SVG при перезапуске. Он тоже требует `SU_TEST_DATABASE_URL` и предварительной сборки.

Отпечаток SHA-256 строится автоматически из упорядоченных метаданных и точных байтов всех SVG. Его меняют новый ID, подпись, категория, порядок и даже изменение рисунка под прежним именем. Вручную версию не редактируйте.

1. Выполните `pnpm build` из одной ревизии: Vite встраивает версию в клиент, esbuild — в сервер. Сборщик проверяет совпадение отпечатков до упаковки сервера.
2. Выпускайте `dist/client` и `dist/server` одним согласованным комплектом. Vite создаёт `dist/client/reaction-release.json`; не редактируйте его вручную. Скомпилированный сервер при запуске проверяет этот манифест и фактические `dist/client/reactions/*.svg` против встроенной версии и откажет при разъезде, в том числе при изменении только подписи. Сервер сохраняет снимок байтов на время процесса, поэтому изменение контента требует перезапуска; в `pnpm dev` тоже перезапустите процесс после изменения SVG/каталога.
3. `/api/world` публикует `catalogVersions.reactions`; клиент проверяет всю карту до подготовки мира/входа и после перезапуска, сервер повторно проверяет её при JOIN. Карта содержит также `animations`; изменение или отсутствие любого ключа требует перезагрузки даже при одинаковом протоколе. Клиентская карта находится в `apps/client/src/presentation/catalog-versions.ts`, `reaction-release.ts` предоставляет версию и URL реакций. Протокол **25** объединяет команды чата, `/speed`, автобусы, LOD/HLOD мира v6 и проверку коллекций: старые вкладки до v25 должны обновиться. Автоматического горячего принятия неизвестных ID нет.
4. URL изображения содержит `?v=<отпечаток>`. Только совпадающая версия получает immutable-кеш; чужая версия возвращает 410/no-store. HTML приложения и `/api/world` нельзя кешировать как immutable. После атомарной замены комплекта проверьте readiness, старую вкладку (должна потребовать обновление) и новую вкладку (должна входить). Активные реакции между процессами не сохраняются; миграция БД для обычного стикера не нужна.

Общие соглашения и порядок интеграции с анимациями/предметами — [Коллекции S-29](collections.md). Поиск/полоса категорий меняют только интерфейс реакций; механики и общий `CatalogShortcuts` других коллекций не заменены. Виртуализация, внешний каталог, импорт тяжёлых моделей/клипов и новые способы управления остаются отдельными направлениями после измерений.
