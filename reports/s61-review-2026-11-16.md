Основные места: [группы](../apps/client/src/streaming/groups.ts), [камера/туман/кастеры](../apps/client/src/rendering/world-view.ts), [тени](../apps/client/src/rendering/environment/lighting.ts), [осадки](../apps/client/src/rendering/environment/precipitation.ts), [общие коллайдеры](../packages/simulation/src/building-colliders.ts).

Изменение `ShadowGenerator.mapSize` в Babylon пересоздаёт RTT, сохраняет renderList, но не пользовательские map-observers. Поэтому при каждом upgrade вновь подключаются static cache и копирование глубины; устаревший held depth не используется с новым RTT. Экономичный режим сохраняет маленькие генераторы, поскольку ссылки на них принадлежат views и материалам. Это ограниченная аллокация, а не утверждение об абсолютно нулевой памяти теней.

Новый spatial index рассмотрен по `add`, повторному retain/remove, `without`, `suspend`, `transferTo` и `dispose`. Составление world-XZ bounds включает локальный transform collider и world transform здания. Пропуск ignored IDs и расширенный поиск для surfaceTolerance сохранены. Сервер и клиент продолжают использовать одну реализацию, исходные colliders, narrow phase и timestep. Численного подтверждения эквивалентности на железе в этом запуске нет.

В остальных исходных изменениях сохранены: R16F targets с существующим PCF, отсутствие немедленной регистрации обычных кастеров на spawn, guard shadowed-батчей, freeze статичных far meshes, throttling tree occlusion при покадровом fade, early-outs с нулевым результатом для сухих/вертикальных поверхностей, version/GPU-buffer guard ночного UBO, прямой BufferSource для native SHA, HTTP immutable для assets и группировка DOM-чтений. Крупных перестроек формата мира, загрузчика или физики это ревью не добавляет. Некоторые DOM-чтения при появлении ранее скрытой chat-метки всё ещё остаются после показа: полное устранение layout flush не заявляется.

**Связь с предыдущими выводами и оставшийся объём**

Игровые сутки (24 реальные минуты), синхронизация времени и порог света 0,1° не менялись. Даже на фиксированном часе остаются caster/streaming/shader invalidations; ночные провалы с Δ=0 не объясняются частотой static refresh. Замедление суток и увеличение порога теней сейчас не обоснованы контролируемым A/B. Сохранять плавное освещение с редкой shadow projection следует отдельным решением с согласованными матрицами обеих карт.

Новые workers, WASM threads и OffscreenCanvas не добавлялись. Предыдущая проверка pinned Havok показала память без флага shared; число логических CPU не измеряет насыщение main thread. Сначала нужны стеки и устранение повторов. Workers могут помочь в подготовке ресурсов/валидации/геометрии, но не сократить GPU-проходы HDR/MSAA, overdraw и Bloom. Из этого diff нельзя вывести долю занятых ядер или ускорение от pool.

Быстрый поворот всё ещё может вызывать чередование визуального far/near и синхронную подготовку/публикацию моделей. Исправлены конкретные ошибки сохранения результата и приоритета; общий temporal LOD debounce или preload всех near не вводился без профиля и оценки памяти. Бюджет 2/6 мс всё ещё проверяется между неделимыми операциями, а не прерывает их. `reconcileNear`/residency и shader compilation могут превышать этот бюджет.

Глобальный скалярный readyRadius по фрустуму продолжает ограничивать дальность всей сцены. Корректность восстановлена без сглаживания вниз за пределы готового покрытия, но архитектурный S-52 этим не закрыт. Для полного решения нужны стабильные fallback/coverage по направлениям и соответствующие браузерные проверки.

Стартовый default quality остаётся standard, настройки HDR/MSAA/теней не разделены. HTTP-сжатие бинарных assets, все предложения по GLB, UBO/шейдерам и подготовке вне main в исходном коммите не реализованы полностью. Их не следует считать завершёнными по этому ревью. В частности, metal-wave fade в wall shader унаследован с зависимостью, усиливающей волну при росте footprint; его визуальную коррекцию следует согласовать с эталонными кадрами отдельно. В shader-ветке этого follow-up дополнительных художественных изменений нет.
