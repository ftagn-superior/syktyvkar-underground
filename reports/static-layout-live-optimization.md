# Фоновая публикация и локальные изменения статики

Дата: 13 ноября 2026 года. Исторический срез до интеграции с последующими изменениями `main`, основа: `69b0c23`. Протокол 16, мир v5, ячейки v2, PostgreSQL v6. Развёртывание не выполнялось.

Версии и результаты ниже относятся к этому срезу и не перенумеровываются после интеграции. Актуальные контракты объединённой версии приведены в [архитектуре](../docs/architecture.md); проверка интеграции фиксируется отдельно.

## Воспроизведение

Нужны зависимости lockfile, Node.js ≥24, локальная PostgreSQL и установленный Chromium Playwright. `SU_TEST_DATABASE_URL` должен указывать на тестовую БД; фикстуры создают отдельные случайные схемы и удаляют их после закрытия. Пользовательские аккаунты и рабочая расстановка не меняются.

```sh
pnpm check
pnpm test --fileParallelism --maxWorkers=4 --testTimeout=120000 --hookTimeout=120000
pnpm build
pnpm world:catalog:check
pnpm test:static-placement:browser
pnpm test:static-removal:browser
pnpm test:static-removal:city
SU_STATIC_PLACEMENT_WORLD=ring-block pnpm test:static-placement:browser
node --import tsx tests/static-layout-live-profile.ts
```

Профиль по умолчанию выполняет 30 успешных созданий и 30 удалений отдельно с двумя и тремя клиентами: автор SDK и один/два настоящих браузерных наблюдателя, одинаковые Chromium/SwiftShader и economy. Cooldown и искусственно задержанная проба учитываются отдельно. `SU_LAYOUT_PROFILE_OPERATIONS`, `SU_LAYOUT_PROFILE_CLIENTS` и `SU_LAYOUT_PROFILE_OUTPUT` позволяют выполнить диагностический короткий прогон. JSON содержит стадийные времена, выборку тиков/поз, HTTP и клиентские счётчики. Размер полной публикации не считается клиентским трафиком.

## Результаты проверки

Финальный полный Vitest с настоящей PostgreSQL: **116 файлов, 772 теста, все прошли**, 111,75 с, четыре независимых процесса. SQL-наборы не пропущены. Проходят TypeScript, границы пакетов, проверка исходных и опубликованных каталогов, сборка миров/клиента/сервера/worker и `git diff --check`. На стенде отсутствовал `pnpm` в PATH; установленные команды scripts запускались непосредственно через Node.js.

Built worker отдельно запущен из `dist/server/preparation-worker.mjs`: все 922 файла записаны, manifest идентичен исходному издателю; обслужено 206 таймерных интервалов по 5 мс во время подготовки. Это проверка built-артефакта, не замер пользовательской задержки. Артефакт: `output/static-live-built-worker.json`.

Подтверждения `areaReady`/`layoutApplied` отправляются сразу после проверки готовности, без ожидания следующего графического кадра. Во время локального `preparing` продолжаются RAF, streaming, камера и HTML-интерфейс; тяжёлый render сцены ждёт завершения подготовки. Неизменившиеся игроки продолжают обычный render. Время получения ответа worker, adoption и очистка каталогов измеряются раздельно; дублирующий staging очищается после клиентских подтверждений. Shutdown сохраняет подтверждённые текущую/предыдущую публикации.

Браузерная маленькая фикстура размещения прошла реальными кликами, включая первый потерянный окончательный ответ, повтор UUID, коллизии наблюдателя и восстановление после перезапуска. Фикстура удаления прошла для исходного дома вне палитры, скамейки общей модели и дерева; проверены отмена, первое лицо, blur, потеря ответа и рестарт. Ошибок браузера нет. Артефакты: `output/playwright/static-placement.json`, `output/playwright/static-removal/result.json` и PNG.

Стенд сравнения: Linux, Node.js 26.10.0, PostgreSQL 17.9, AMD EPYC-Rome-v4 / 8 логических CPU, Chromium 158 / SwiftShader, economy. Исходная версия `69b0c23` собрана в отдельной `/tmp`-копии с теми же зависимостями и собственным каталогом мира. В каждом варианте отдельно два и три клиента, по 30 успешных созданий и удалений; два дополнительных изменения относятся к пробе задержанного клиента и исключены из тёплых перцентилей. Автор — SDK, наблюдатели — настоящие браузеры. Реальные пользовательские инструменты проверены отдельными браузерными сценариями.

Все 120 измеренных операций успешны. Во время каждой подготовки наблюдатель двигался и сервер выполнил не менее 18 тиков; максимальный наблюдавшийся интервал таймера во время подготовки — 61,67 мс. Пауза p95 ≤100 мс / max ≤250 мс и тёплая готовность ≤1 с достигнуты на этом стенде. Готовность означает перевод streaming/физики и подтверждение клиента; это не замер GPU presentation/FPS. Освобождение редакторского слота включает последующую очистку файлов и показано отдельно.

При искусственной задержке одного manifest на 5 с с тремя клиентами пауза составила **12,96 мс**, сервер выполнил **318 тиков**, здоровый браузерный наблюдатель прошёл **11 м**. Предыдущая публикация удерживалась до нужных подтверждений; симуляция продолжалась.

Исходная версия пересоздала PredictionWorld 62 раза на браузер (счётчик 1 → 63). В итоговой версии каждый браузер сохранил **1 → 1**, импортов уже удерживаемых GLB — **0**, создано/удалено ровно по **31** экземпляру с учётом отдельной пробы медленного клиента. Пересозданий земли и границ — **0**. Числа статичных объектов, ссылок, моделей, Havok-тел и разобранных коллизий вернулись к исходным значениям: 2488 объектов / 2649 ссылок / 377 486 байт разобранных коллизий; тела — 2491 при двух клиентах и 2492 при трёх. Общий LRU вырос с 8 566 612 до 9 275 055 байт и остался существенно ниже 64 МиБ.

В наблюдавшихся ответах live-загрузки были только manifest и новые JSON ячеек; повторных GLB, collider или graphics-pack запросов не было. Playwright Content-Length не выдаётся за фактический TCP-трафик: ответы могут обслуживаться HTTP-кешем. Полный размер публикации около 20,7 МБ относится к файловой работе worker, а не к передаче клиенту.

Стадии p95 при трёх клиентах (создание / удаление), мс: worker build **309,51 / 344,38**, write **131,26 / 133,04**, доставка результата worker **7,89 / 8,65**, adopt **6,06 / 2,86**, ожидание финального writer **2,22 / 3,53**, проверка геометрии **5,42 / <0,01**, flush **5,56 / 6,50**, SQL commit **7,88 / 5,50**, Havok apply **0,88 / 0,26**. Очистка после подтверждений — **0,03 / 265,46**, срок удержания предыдущей публикации — **287,26 / 234,93**. Перцентили стадий считаются отдельно и не суммируются. Клиентские длительности догрузки/локальной паузы и cache hits доступны в diagnostics; последний графический swap занял 5,4–7,2 мс, это отдельные пробы, не p95 всей серии.

Холодные входы итоговой серии: 4,33 с при двух клиентах, 3,83 / 10,81 с при трёх. Они не смешаны с тёплыми операциями. Дополнительная проба с тремя клиентами дала входы 5,91/9,74 с, локальную spawn-подготовку 1,64/1,86 с и 60/66 кадров, отданных подготовке. Начальный неуспешный прогон на промежуточном коде обнаружил зависимость handshake от render и PREPARE_TIMEOUT; после исправления итоговые серии прошли без увеличения лимитов.

Настоящий город, финальный `/vilievna`: реальным указателем удалён `osm-way-89626599` («Октябрьский проспект, 49/1»), БД сохранила `enabled=false` и instance revision 2, оба клиента обновились, соседняя сцена сохранилась. Первый холодный worker дал 1642,11 мс подготовки; время сценария от подтверждения 2307,62 мс, общая пауза **21,36 мс**, клиентские подтверждения через 158,17/244,05 мс после применения. Ошибок браузера нет. PNG до/после визуально проверены.

Настоящий город, финальный `/motherlode`: все 22 модели показали карточки, 3D-превью и ghost; четыре занятых места корректно дали `BLOCKED`, затем скамейка сохранена на ревизии 3708. Оба браузера увидели экземпляр, проверен проход/столкновение наблюдателя, потерянный первый ответ разрешён replay того же UUID, перезапуск сохранил объект. Подготовка успешного запроса **372,03 мс**, общая пауза **22,53 мс**, подтверждения клиентов через **161,26/244,45 мс** после применения. Ошибок браузера нет.

Итоговые JSON: `output/static-layout-baseline/`, `output/static-layout-live-profile-final/`, `output/playwright/static-removal-city/`, `output/playwright/static-placement-city.json`; каталог `output/` игнорируется Git. Промежуточные неуспешные/медленные прогоны сохранены отдельно и не включены в итоговые перцентили.

## Интеграция с обновлённым main

Изменения объединены с `main` на основе `65ec214`, включая сохранение позиции аккаунта, погоду, управление с геймпада и ночное освещение. Контракт объединённого приложения — протокол **19**, мир v5, ячейки v2, PostgreSQL **v7**; схема v7 добавляет `player_positions` и сохраняется без отката к v6.

После rebase проходят TypeScript, границы пакетов, проверка исходных/опубликованных каталогов, пересборка всех миров, клиента, сервера и worker, а также `git diff --check`. Полный прогон объединённой версии: **130 файлов, 893 теста; 890 прошли, 3 упали** за 113,19 с. Все SQL-наборы выполнялись на настоящей PostgreSQL в отдельных временных схемах.

Три сбоя подтверждены и на независимой архивной копии чистого `main` `65ec214`: **9 passed / 3 failed** в тех же двух файлах, с идентичными Expected/Received хешами. Это существующее расхождение исторических эталонов после NightGlow:

- `static-asset-library-preflight.test.ts`: текущий asset release не равен зафиксированному target старой миграции;
- `static-object-extraction.test.ts`: общий library hash больше не равен историческому эталону;
- `static-object-extraction.test.ts`: в authoring allowlist не учтены добавленные `windowGlow`/`glow`.

Геометрический бюджет не нарушен: отдельная сверка 1106 профилей растительности дала максимум 9,77% при лимите 10%; нормализация только подтверждённых NightGlow-полей возвращает все 138 исходных authoring hashes. Эталоны и исторические migration rules ради зелёного прогона не переписывались. Свидетельства: `output/static-live-rebase-tests.log`, `output/static-live-main-baseline-tests.log`, `output/static-live-upstream-regression-analysis.json`.

Дополнительно прошла интеграционная браузерная проба на новом городе: три клиента, создание и удаление, задержанный на 5 с клиент, движение здорового наблюдателя, сохранение PredictionWorld и нулевые лишние импорты/пересоздания. Единичные тёплые готовности 722,32/700,46 мс, общие паузы 17,11/6,20 мс; это smoke samples, не повторная серия p95. Артефакты: `output/static-live-rebase-smoke.log`, `output/static-layout-live-rebased-smoke/`.

Приведённые выше 772 теста, городские серии и перцентили относятся к историческому срезу протокола 16 / БД v6; повторная серия из 120 операций после интеграции не запускалась.

## Границы

Короткая пауза финального writer остаётся. Неопределённый commit и отказ хранилища сохраняют безопасную общую остановку. Следующая static-правка ждёт подтверждений/выходов/15-секундного таймаута предыдущего перехода. Полная подготовка сохраняется для несовместимой основы, пропущенной ревизии и перезапуска. Производительность аппаратного GPU требует отдельного стенда; SwiftShader подтверждает функциональные сценарии и сравнение одинаковых программных прогонов.
